## 二、设计巧思

### 2.1 混合搜索三表达式融合

**文件**: [rag/nlp/search.py:249](../../rag/nlp/search.py)

```python
matchText, keywords = self.qryr.question(qst, min_match=0.3)        # BM25 全文匹配
matchDense = await self.get_vector(qst, emb_mdl, topk, ...)         # 向量匹配
fusionExpr = FusionExpr("weighted_sum", topk, {"weights": "0.05,0.95"})  # 加权融合

matchExprs = [matchText, matchDense, fusionExpr]
```

三个表达式同时传入存储引擎，由引擎层完成融合计算：
- `matchText`: BM25 稀疏检索，负责精确词匹配
- `matchDense`: 向量稠密检索，负责语义相似性
- `fusionExpr`: `weighted_sum` 融合策略，初始权重文本 5% + 向量 95%

这种设计将融合逻辑下沉到存储引擎层，避免应用层多次查询和二次排序的开销。

### 2.2 向量主导的初始检索权重

**文件**: [rag/nlp/search.py:249](../../rag/nlp/search.py)

初始融合权重 `{"weights": "0.05,0.95"}` 即文本 5%、向量 95%，采用**向量主导**策略：
- 向量检索天然具有语义理解能力，能捕获同义词和相关概念
- BM25 文本检索在此阶段主要起**辅助筛选**作用，过滤掉完全无关的结果
- 这种分配在初始召回阶段最大化语义召回率

### 2.3 权重放大策略（多级关键词增强）

**文件**: [rag/nlp/search.py:481](../../rag/nlp/search.py)

```python
tks = content_ltks + title_tks * 2 + important_kwd * 5 + question_tks * 6
```

重排序阶段对特定字段的关键词进行倍率放大：
| 字段 | 放大倍数 | 设计意图 |
|------|----------|----------|
| `content_ltks` | x1 | 正文基础匹配 |
| `title_tks` | x2 | 标题出现的关键词重要性更高 |
| `important_kwd` | x5 | 用户标注的重要关键词权重极高 |
| `question_tks` | x6 | 文档中的问题文本（FAQ 场景）权重最高 |

同样，`FulltextQueryer` 中查询字段权重设置也体现了类似思想：
- `important_kwd^30`: 重要关键词在检索时权重 30
- `question_tks^20`: 问题文本在检索时权重 20
- `title_tks^10`: 标题在检索时权重 10

### 2.4 无结果自动降级机制

**文件**: [rag/nlp/search.py:258-269](../../rag/nlp/search.py)

```python
if total == 0:
    if filters.get("doc_id"):
        # 指定文档内搜索失败 → 退化为无条件搜索
        res = await thread_pool_exec(self.dataStore.search, src, [], filters, [], ...)
    else:
        # 全局搜索失败 → 降低 min_match 和 similarity 阈值
        matchText, _ = self.qryr.question(qst, min_match=0.1)  # 0.3 → 0.1
        matchDense.extra_options["similarity"] = 0.17           # 0.1 → 0.17（注意：向量阈值上调）
        res = await thread_pool_exec(self.dataStore.search, src, highlightFields, filters,
                                     [matchText, matchDense, fusionExpr], ...)
```

两级降级策略：
1. **降低文本匹配度要求**: `min_match` 从 30% 降至 10%，允许更少的关键词命中
2. **调整向量相似度**: 将向量阈值提高到 0.17，结合更宽松的文本条件重新召回

### 2.5 RERANK_LIMIT 超量获取策略

**文件**: [rag/nlp/search.py:595-596](../../rag/nlp/search.py)

```python
RERANK_LIMIT = math.ceil(64 / page_size) * page_size if page_size > 1 else 1
RERANK_LIMIT = max(30, RERANK_LIMIT)
```

设计意图：
- 先获取远大于 `page_size` 的候选集（最少 30 个），为重排序提供足够的候选池
- 重排序后再进行阈值过滤和分页，确保最终返回的高质量结果数量充足
- 这是一种典型的 **"召回宽、排序严"** 策略

### 2.7 父子块检索（Parent-Child Chunk Retrieval）

**文件**: [rag/nlp/search.py:965](../../rag/nlp/search.py)

```python
def retrieval_by_children(self, chunks: list[dict], tenant_ids: list[str]):
    mom_chunks = defaultdict(list)
    while i < len(chunks):
        mom_id = ck.get("mom_id")
        if not isinstance(mom_id, str) or not mom_id.strip():
            i += 1
            continue
        mom_chunks[ck["mom_id"]].append(chunks.pop(i))  # 按父块分组
```

设计思路：
- 检索阶段匹配的是细粒度的子块（高精度）
- 结果展示阶段替换为粗粒度的父块（完整上下文）
- 父块相似度 = 所有子块相似度的均值
- 解决了"精确匹配"与"完整上下文"之间的矛盾

### 2.9 GraphRAG 多路召回

**文件**: [rag/graphrag/search.py:226](../../rag/graphrag/search.py)

```python
async def retrieval(self, question, tenant_ids, kb_ids, emb_mdl, llm, ...):
    # 1. LLM 查询重写 → 提取实体类型 + 实体
    ty_kwds, ents = await self.query_rewrite(llm, qst, idxnms, kb_ids)

    # 2. 三路并行召回
    ents_from_query = self.get_relevant_ents_by_keywords(ents, ...)      # 按关键词召回实体
    ents_from_types = self.get_relevant_ents_by_types(ty_kwds, ...)      # 按类型召回实体
    rels_from_txt = self.get_relevant_relations_by_txt(qst, ...)          # 按文本召回关系

    # 3. N-hop 路径扩展
    for _, ent in ents_from_query.items():
        nhops = ent.get("n_hop_ents", [])

    # 4. 联合打分: sim * pagerank
    ents_from_query = sorted(..., key=lambda x: x[1]["sim"] * x[1]["pagerank"], reverse=True)

    # 5. 社区报告召回
    self._community_retrieval_(entities, condition, kb_ids, idxnms, comm_topn, max_token)
```

五路召回融合：
1. **实体关键词召回**: 根据查询提取的实体名称在向量空间中匹配
2. **实体类型召回**: 根据 LLM 提取的实体类型过滤高 PageRank 实体
3. **关系文本召回**: 根据查询文本在向量空间中匹配关系三元组
4. **N-hop 路径扩展**: 从匹配实体出发，沿图谱路径发现隐含关系
5. **社区报告召回**: 匹配包含相关实体的社区摘要

评分机制采用 `sim * pagerank`，结合语义相似度和图结构重要性。

## 三、架构模式学习

### 3.1 混合检索架构（Hybrid Search: Dense + Sparse + Fusion）

```
用户问题
   │
   ├──────────────────┬──────────────────┐
   ▼                  ▼                  ▼
FulltextQueryer    Embedding Model    FusionExpr
(BM25 Sparse)     (Dense Vector)    (Weighted Sum)
   │                  │                  │
   ▼                  ▼                  ▼
 MatchTextExpr     MatchDenseExpr    FusionExpr
   │                  │                  │
   └──────────────────┴──────────────────┘
                      │
                      ▼
              dataStore.search()
           (ES/Infinity/OpenSearch)
                      │
                      ▼
                 融合排序结果
```

关键设计：三种表达式在同一层传给存储引擎，由引擎在底层完成融合计算，减少数据传输和二次排序开销。

### 3.2 多级重排序策略

```
初始检索结果（RERANK_LIMIT 个候选）
   │
   ├── 有 Rerank 模型？
   │     ├─ 是 → rerank_by_model()
   │     │        LLM Rerank 模型计算语义相似度
   │     │        score = tkweight * tksim + vtweight * vtsim + rank_fea
   │     │
   │     └─ 否 → 判断存储引擎类型
   │              ├─ Infinity → 直接使用引擎融合分数（引擎已归一化）
   │              │
   │              └─ ES → rerank() 本地混合重排序
   │                      构建增强词袋 + hybrid_similarity() + rank_fea
   │
   ▼
相似度阈值过滤 → 分页返回
```

三种重排序策略的选择逻辑：
| 条件 | 策略 | 原因 |
|------|------|------|
| 有 Rerank 模型 | `rerank_by_model()` | 最精确，利用专用的 Cross-Encoder 模型 |
| Infinity 引擎 | 直接用引擎分数 | Infinity 内部已对各路分数归一化后再融合 |
| ES 引擎 | `rerank()` 本地混合 | ES 融合时未归一化各路分数，需应用层重排 |

- `DeepResearcher` 模式下，`retrieval` 被包装为 `partial` 传入，由推理引擎自主调用

### 3.4 Dealer 代理模式（Proxy Pattern）

```python
class Dealer:
    def __init__(self, dataStore: DocStoreConnection):
        self.qryr = query.FulltextQueryer()   # 查询构建代理
        self.dataStore = dataStore              # 存储引擎代理
```

`Dealer` 作为检索代理类，封装了对不同存储引擎的访问：
- 上层只需调用 `Dealer.retrieval()`，无需关心底层存储是 ES 还是 Infinity
- `Dealer` 持有 `FulltextQueryer`（查询构建）和 `DocStoreConnection`（存储访问）两个代理
- 通过组合而非继承实现功能扩展

```python
    src.append(f"q_{len(q_vec)}_vec")   # ES 需要显式请求向量字段

# retrieval() 中的条件分支
if settings.DOC_ENGINE_INFINITY:
    sim = [sres.field[id].get("_score", 0.0) for id in sres.ids]  # Infinity 分数可直接用
else:
    sim, tsim, vsim = self.rerank(...)  # ES 需要本地重排序
```

引擎差异处理策略：
| 特性 | Elasticsearch | Infinity |
|------|--------------|----------|
| 向量字段请求 | 需显式添加 `q_N_vec` | 自动包含 |
| 融合分数 | 未归一化，需本地重排 | 已归一化，直接使用 |
| SQL 表名 | `ragflow_{tenant_id}` | `ragflow_{tenant_id}_{kb_id}` |

## 六、关键配置参数表

### 6.1 检索参数

| 参数 | 默认值 | 位置 | 说明 |
|------|--------|------|------|
| `similarity_threshold` | 0.2 | `Dealer.retrieval()` | 相似度阈值，低于此值的结果被过滤 |
| `vector_similarity_weight` | 0.3 | `Dealer.retrieval()` | 向量相似度权重（词元权重 = 1 - 此值） |
| `top` (topk) | 1024 | `Dealer.retrieval()` | 向量检索返回的候选数 |
| `RERANK_LIMIT` | max(30, ceil(64/page_size)*page_size) | `Dealer.retrieval()` | 重排序候选池大小 |
| `page_size` | `dialog.top_n` | `async_chat()` | 最终返回的文档块数量 |

### 6.2 融合权重

| 参数 | 值 | 位置 | 说明 |
|------|-----|------|------|
| 初始融合权重 | `"0.05,0.95"` (文本5%,向量95%) | `Dealer.search()` | 存储引擎层融合 |
| 重排序默认权重 | `tkweight=0.3, vtweight=0.7` | `Dealer.rerank()` | 应用层重排序 |
| 模型重排序权重 | `tkweight=0.3, vtweight=0.7` | `Dealer.rerank_by_model()` | 模型重排序 |
| 引用插入权重 | `tkweight=0.1, vtweight=0.9` | `Dealer.insert_citations()` | 引用匹配 |

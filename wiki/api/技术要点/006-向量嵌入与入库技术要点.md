## 二、设计巧思

### 1. 文件名向量广播优化（encode once, np.tile to all）

**核心思想**：同一文档的所有 chunk 共享同一个文件名，只需调用一次嵌入 API 编码文件名，然后用 `np.tile` 将向量复制到所有 chunk。

```python
# rag/svr/task_executor.py:746-747
vts, c = await thread_pool_exec(mdl.encode, tts[0:1])   # 只编码第一个文件名
tts = np.tile(vts[0], (len(cnts), 1))                    # 广播到全部 chunk
```

**收益**：假设一篇文档被切分为 200 个 chunk，这一优化直接节省了 199 次嵌入 API 调用。在批量处理场景下，这个节省非常可观。

---

### 2. 双通道加权混合向量

**核心思想**：最终向量 = `0.1 * 文件名向量 + 0.9 * 内容向量`，通过权重控制文件名语义在检索中的影响力。

```python
# rag/svr/task_executor.py:769-775
filename_embd_weight = parser_config.get("filename_embd_weight", 0.1)
title_w = float(filename_embd_weight)
if tts.ndim == 2 and cnts.ndim == 2 and tts.shape == cnts.shape:
    vects = title_w * tts + (1 - title_w) * cnts
else:
    vects = cnts  # 维度不匹配时回退到纯内容向量
```

**设计考量**：
- 默认权重 `0.1` 使得文件名只作为检索的微弱信号，不会喧宾夺主
- 用户可通过 `parser_config.filename_embd_weight` 自定义权重
- 维度安全检查：当 `tts` 和 `cnts` 维度不匹配时回退到纯内容向量

---

### 3. 问题关键词优先嵌入

**核心思想**：如果用户为 chunk 设置了 `question_kwd`（问题关键词），则优先用关键词文本做嵌入，而非原始内容。

```python
# rag/svr/task_executor.py:734-736
c = "\n".join(d.get("question_kwd", []))
if not c:
    c = d["content_with_weight"]
```

**收益**：`question_kwd` 是用户精心挑选的、最能代表该 chunk 检索意图的关键词。用关键词嵌入能让检索更精准，减少噪声。

---

### 4. HTML 标签清理

**核心思想**：在嵌入前移除 HTML 表格标签（`table`/`td`/`tr`/`th`/`caption`），避免标签文本干扰向量语义。

```python
# rag/svr/task_executor.py:738
c = re.sub(r"</?(table|td|caption|tr|th)( [^<>]{0,12})?>", " ", c)
```

**设计考量**：文档解析后可能残留 HTML 标记，特别是表格类内容。这些标签本身不携带语义信息，反而会稀释有效文本的嵌入质量。

---

### 5. 文本截断双保险

**核心思想**：在嵌入链路的两层分别实施 Token 截断，形成双重保护。

**第一层 - batch_encode 中调用 truncate()**：
```python
# rag/svr/task_executor.py:752-754
def batch_encode(txts):
    return mdl.encode([truncate(c, mdl.max_length - 10) for c in txts])
```
使用 `max_length - 10` 预留 10 个 token 的安全余量，`truncate()` 基于 tiktoken 编码器在 token 级别精确截断（而非字符级别）。

**第二层 - LLMBundle.encode() 中按 token 数截断**：
```python
# api/db/services/llm_service.py:101-104
token_size = num_tokens_from_string(text)
if token_size > self.max_length:
    target_len = int(self.max_length * 0.95)
    safe_texts.append(text[:target_len])
```
在模型调用层再做一次 0.95 倍截断保护，防止超长文本导致 API 报错。

---

### 6. 母 chunk 精简存储

**核心思想**：母 chunk（mother chunk）只保留核心字段，不存储向量，`available_int=0` 标记为不可检索。

```python
# rag/svr/task_executor.py:1128-1136
mom_ck = copy.deepcopy(ck)
mom_ck["id"] = id
mom_ck["content_with_weight"] = mom
mom_ck["available_int"] = 0  # 不可检索
flds = list(mom_ck.keys())
for fld in flds:
    if fld not in ["id", "content_with_weight", "doc_id", "docnm_kwd",
                   "kb_id", "available_int", "position_int",
                   "create_timestamp_flt", "page_num_int", "top_int"]:
        del mom_ck[fld]
```

**设计意图**：
- 母 chunk 是完整的上下文文本，仅供子 chunk 通过 `mom_id` 引用
- `available_int=0` 确保母 chunk 不出现在检索结果中
- 删除向量字段大幅节省存储空间（一个向量通常几百到几千字节）

---

### 7. 分批插入 + 取消检查

**核心思想**：每批插入后立即检查任务是否被取消，实现快速响应取消操作。

```python
# rag/svr/task_executor.py:1149-1155
for b in range(0, len(chunks), settings.DOC_BULK_SIZE):
    doc_store_result = await thread_pool_exec(
        settings.docStoreConn.insert,
        chunks[b:b + settings.DOC_BULK_SIZE],
        search.index_name(task_tenant_id), task_dataset_id)
    task_canceled = has_canceled(task_id)
    if task_canceled:
        progress_callback(-1, msg="Task has been canceled.")
        return False
```

**收益**：用户取消操作时，不需要等待全部数据插入完毕，而是在当前批次完成后立即停止。

---

### 8. 断点续传机制

**核心思想**：每批插入成功后，将已插入的 chunk_ids 记录到任务表中。如果任务中断，可以从断点恢复。

```python
# rag/svr/task_executor.py:1162-1167
chunk_ids = [chunk["id"] for chunk in chunks[:b + settings.DOC_BULK_SIZE]]
chunk_ids_str = " ".join(chunk_ids)
try:
    TaskService.update_chunk_ids(task_id, chunk_ids_str)
except DoesNotExist:
    # 任务已被删除，回滚已插入的数据
    doc_store_result = await thread_pool_exec(
        settings.docStoreConn.delete,
        {"id": chunk_ids},
        search.index_name(task_tenant_id), task_dataset_id)
```

**设计考量**：当任务对应的 Task 记录已被删除（说明用户删了文档或知识库），已插入的数据必须回滚清理，否则会产生孤儿数据。

---

### 9. ES Bulk API 延迟刷新

**核心思想**：ES 的 `insert()` 使用 `refresh=False`，不立即刷新索引，以换取更高的写入吞吐量。

```python
# rag/utils/es_conn.py:314-315
r = self.es.bulk(index=index_name, operations=operations,
                 refresh=False, timeout="60s")
```

**收益**：ES 的 refresh 操作开销较大（涉及 segment 合并）。延迟刷新让 ES 自行在后台周期性刷新（默认每秒一次），大幅提升批量写入性能。

---

### 10. 进度区间分配

**核心思想**：整个文档处理流程通过进度区间划分不同阶段，前端可据此展示精确的处理进度。

| 阶段 | 进度区间 | 代码位置 |
|------|----------|----------|
| 文档分块 (build_chunks) | 0.0 - 0.7 | [task_executor.py:1394](../../rag/svr/task_executor.py) |
| 向量嵌入 (embedding) | 0.7 - 0.9 | [task_executor.py:766](../../rag/svr/task_executor.py) |
| 数据入库 (insert_chunks) | 0.8 - 0.9 | [task_executor.py:1157](../../rag/svr/task_executor.py) |
| 完成收尾 | 0.9 - 1.0 | [task_executor.py:1463](../../rag/svr/task_executor.py) |

嵌入阶段的进度计算：
```python

```

入库阶段的进度计算（每 128 批更新一次）：

## 三、架构模式学习

### 1. 存储引擎抽象（Strategy Pattern）

通过 `docStoreConn` 接口抽象文档存储操作，运行时根据 `DOC_ENGINE` 环境变量选择具体实现。

```python
# common/settings.py:260-285
DOC_ENGINE = os.environ.get("DOC_ENGINE", "elasticsearch").strip()
if lower_case_doc_engine == "elasticsearch":
    docStoreConn = rag.utils.es_conn.ESConnection()
elif lower_case_doc_engine == "infinity":
    docStoreConn = rag.utils.infinity_conn.InfinityConnection()
elif lower_case_doc_engine == "opensearch":
    docStoreConn = rag.utils.opensearch_conn.OSConnection()
elif lower_case_doc_engine == "oceanbase":
    docStoreConn = rag.utils.ob_conn.OBConnection()
```

**模式价值**：上层业务代码（`embedding()`、`insert_chunks()`）完全不关心底层存储引擎类型，通过统一接口 `settings.docStoreConn.insert()` / `.search()` / `.delete()` 操作。

---

### 2. 线程池卸载同步 IO

所有存储操作（ES/Infinity 网络调用）都是同步的，通过 `thread_pool_exec` 卸载到线程池，避免阻塞异步事件循环。

```python
# common/misc_utils.py:128-133
async def thread_pool_exec(func, *args, **kwargs):
    loop = asyncio.get_running_loop()
    if kwargs:
        func = functools.partial(func, *args, **kwargs)
        return await loop.run_in_executor(_thread_pool_executor(), func)
    return await loop.run_in_executor(_thread_pool_executor(), func, *args)
```

**使用场景**：
- 嵌入模型调用：`await thread_pool_exec(mdl.encode, texts)`
- ES 批量写入：`await thread_pool_exec(settings.docStoreConn.insert, chunks, ...)`
- 索引创建：`await thread_pool_exec(settings.docStoreConn.create_idx, ...)`

---

### 3. 母子 chunk 层级索引

通过 `mom_id` 字段建立子 chunk 与母 chunk 的关联，实现上下文扩展检索。

```
母 chunk (mom)
  ├── id = xxhash(mom_content)
  ├── content_with_weight = 完整上下文文本
  ├── available_int = 0 (不参与检索)
  └── 无向量字段

子 chunk (child)
  ├── mom_id = 母 chunk 的 id
  ├── content_with_weight = 分块后的片段文本
  ├── available_int = 1 (参与检索)
  └── q_<dim>_vec = 混合向量
```

**应用场景**：检索命中的是子 chunk，通过 `mom_id` 可以获取完整的母 chunk 上下文，提供更丰富的上下文信息给 LLM。

---

### 4. 批量写入 + 重试

ES 连接使用 `ATTEMPT_TIME = 2` 次重试机制，遇到 `ConnectionTimeout` 时自动重连。

```python
# rag/utils/es_conn.py:311-328
for _ in range(ATTEMPT_TIME):
    try:
        r = self.es.bulk(index=index_name, operations=operations,
                         refresh=False, timeout="60s")
        if re.search(r"False", str(r["errors"]), re.IGNORECASE):
            return res  # 成功
        # 收集错误信息
        for item in r["items"]:
            for action in ["create", "delete", "index", "update"]:
                if action in item and "error" in item[action]:
                    res.append(str(item[action]["_id"]) + ":" + str(item[action]["error"]))
        return res
    except ConnectionTimeout:
        self.logger.exception("ES request timeout")
        time.sleep(3)
        self._connect()  # 重新建立连接
        continue
```

**设计考量**：ES 在高负载下可能超时，重试 + 重连机制保证了写入的最终成功。

---

### 5. 最终一致性刷新

`refresh=False` 延迟刷新体现了最终一致性思想：

- **写入时**：数据写入 ES 的内存 buffer，不可检索
- **后台刷新**：ES 默认每秒刷新一次，将 buffer 写入 segment，数据变为可检索
- **显式刷新**：在需要立即检索的场景（如用户手动触发检索），可显式调用 `refresh=True`

这种模式在批量写入场景下显著提升吞吐量，代价是写入后有短暂的不可检索窗口。

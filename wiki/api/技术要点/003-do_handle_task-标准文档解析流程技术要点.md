# do_handle_task 标准文档解析流程技术要点

## 设计关注点

标准解析流程最大的价值，是把“解析、向量化、入库”做成一条可追踪、可取消、可恢复的后台链路。

## 关键技术点

### 1. 任务上下文要完整

执行时通常需要：

- 文档信息
- 知识库信息
- 模型配置
- 页范围或解析配置

### 2. 每个阶段都应该可观测

如果看不到 `build_chunks -> embedding -> insert_chunks` 的阶段切换，排障会非常痛苦。

### 3. 异常和取消是正常路径

任务系统里，失败和取消不是边角料，而是主路径的一部分。

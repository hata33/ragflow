# 标准文档解析流程 - 业务逻辑步骤

## 接口信息
- **模块**: `task_executor` 内部进程（非 HTTP 接口）
- **功能**: 执行标准文档解析任务（分块、嵌入、入库）
- **触发方式**: 由 `do_handle_task` 函数在任务类型为"标准解析"时调用
- **所属流程**: 文档解析接口（`POST /api/v1/document/run`）的后台执行阶段

---

## 业务逻辑流程

### 第一步：提取任务参数
1. 从任务对象中提取以下关键参数：
   - `task_id`：任务唯一标识
   - `from_page` / `to_page`：页码范围（用于 PDF 等分页文档的分片解析）
   - `tenant_id`：租户 ID
   - `embd_id`：嵌入模型 ID
   - `language`：文档语言
   - `parser_config`：解析器配置（含分块大小、分隔符、自动关键词等）
   - `kb_parser_config`：知识库级解析器配置（含标签分类、LLM 等）
   - `llm_id`：LLM 模型 ID
   - `kb_id`：知识库 ID
   - `doc_id`：文档 ID
   - `name`：文档名称
   - `parser_id`：解析器类型标识
2. 确定 LLM 模型 ID 的优先级：
   - 文档级别：优先使用 `parser_config.llm_id`，其次使用任务级的 `llm_id`
   - 知识库级别：优先使用 `kb_parser_config.llm_id`，其次使用任务级的 `llm_id`
   - 最终以知识库级别的 LLM ID 为准（统一 LLM 调用）

---

### 第二步：检查任务取消状态
1. 查询 Redis 中的取消标志，判断该任务是否已被用户取消
2. 如果任务已被取消：
   - 设置进度为错误状态（-1）
   - 记录"任务已取消"消息
   - 直接结束流程，不再执行后续步骤

**可能失败**：任务已被取消 → 终止执行，记录取消消息

---

### 第三步：绑定嵌入模型
1. 根据 `embd_id` 获取嵌入模型的配置信息
   - 如果 `embd_id` 为空，使用租户的默认嵌入模型
2. 创建嵌入模型调用实例（LLMBundle）
3. 执行测试编码（编码"ok"文本），验证模型可用性
4. 从测试编码结果中获取向量维度（`vector_size`），供后续使用

**可能失败**：嵌入模型配置错误或不可用 → 记录"绑定嵌入模型失败"错误，终止任务

---

### 第四步：初始化知识库索引
1. 根据租户 ID 构建索引名称（规则：`ragflow_{租户ID}`）
2. 检查文档存储（Elasticsearch 或 Infinity）中是否已存在该索引
3. 如果索引不存在：
   - 根据向量维度和解析器类型创建新索引
   - 索引结构包含向量字段（`q_{维度}_vec`）、文本字段、元数据字段等

**可能失败**：索引创建失败 → 后续写入将失败

---

### 第五步：构建文档分块（build_chunks）

#### 5.1 检查文件大小限制
1. 检查任务中的文件大小是否超出系统最大限制（`DOC_MAXIMUM_SIZE`）
2. 如果超出限制 → 设置错误进度，返回空列表

**可能失败**：文件大小超限 → 返回错误"文件大小超出限制"

---

#### 5.2 从对象存储获取文件
1. 根据文档 ID 获取文件的存储地址（bucket 和文件名）
2. 从对象存储（MinIO/S3）下载文件的二进制数据
3. 记录下载耗时

**可能失败**：
- MinIO 超时 → 返回"从 MinIO 获取文件超时"错误
- 文件不存在 → 返回"在 MinIO 中找不到文件"错误
- 其他异常 → 返回具体错误信息

---

#### 5.3 选择解析器并执行分块
1. 根据文档的 `parser_id` 从解析器工厂（FACTORY）映射表中选择对应的解析模块：
   | 解析器类型 | 说明 |
   |-----------|------|
   | general / naive | 通用解析器 |
   | paper | 学术论文解析器 |
   | book | 书籍解析器 |
   | presentation | 演示文稿解析器 |
   | manual | 使用手册解析器 |
   | laws | 法律文档解析器 |
   | qa | 问答对解析器 |
   | table | 表格解析器 |
   | resume | 简历解析器 |
   | picture | 图片解析器 |
   | one | 整文档解析器 |
   | audio | 音频解析器 |
   | email | 邮件解析器 |
   | tag | 标签解析器 |
2. 在线程池中执行解析器的分块方法，传入：
   - 文件名、文件二进制数据
   - 页码范围（from_page、to_page）
   - 语言设置
   - 解析器配置（分块大小、分隔符等）
   - 知识库 ID、租户 ID
3. 解析器输出 chunk 列表，每个 chunk 包含：
   - 文本内容
   - 带权重文本（content_with_weight）
   - 位置信息（页码、坐标）
   - 图片数据（如有）
   - 权重值

**可能失败**：不支持的文件格式或解析异常 → 返回"文档分块内部错误"

---

#### 5.4 处理 chunk 中的图片
1. 为每个 chunk 生成唯一 ID（基于内容哈希：xxhash64）
   - 哈希输入：`chunk 的 content_with_weight + 文档 ID`
2. 记录 chunk 的创建时间和时间戳
3. 遍历每个 chunk 的图片，执行图片上传：
   - 如果 chunk 已有 `img_id` → 直接保留，不上传
   - 如果 chunk 无图片 → 设置空 `img_id`
   - 如果 chunk 有图片 → 调用 `image2id` 将图片上传到 MinIO，生成图片 ID
4. 所有图片上传并发执行（受 MinIO 并发信号量控制）

**可能失败**：MinIO 上传异常 → 取消所有上传任务，抛出异常

---

### 第六步：LLM 增强（可选，根据配置逐项执行）

#### 6.1 自动生成关键词（当 `auto_keywords > 0` 时）
1. 获取 Chat 模型配置并创建 LLM 调用实例
2. 对每个 chunk 并发执行关键词提取：
   - 优先查询 LLM 缓存，命中则直接使用
   - 缓存未命中 → 调用 LLM 提取指定数量的关键词
   - 将结果写入 LLM 缓存（避免重复调用）
3. 将关键词附加到 chunk：
   - `important_kwd`：关键词列表
   - `important_tks`：关键词分词结果
4. 每个 chunk 执行前检查任务取消状态

**可能失败**：LLM 调用失败 → 取消所有关键词生成任务，抛出异常

---

#### 6.2 自动生成问题（当 `auto_questions > 0` 时）
1. 获取 Chat 模型配置并创建 LLM 调用实例
2. 对每个 chunk 并发执行问题生成：
   - 优先查询 LLM 缓存
   - 缓存未命中 → 调用 LLM 生成指定数量的相关问题
   - 将结果写入 LLM 缓存
3. 将问题附加到 chunk：
   - `question_kwd`：问题列表（按行分割）
   - `question_tks`：问题分词结果
4. 每个 chunk 执行前检查任务取消状态

**可能失败**：LLM 调用失败 → 取消所有问题生成任务，抛出异常

---

#### 6.3 自动生成元数据（当 `enable_metadata = true` 且 `metadata` 配置存在时）
1. 获取 Chat 模型配置并创建 LLM 调用实例
2. 将元数据配置转换为 JSON Schema 格式
3. 对每个 chunk 并发执行元数据提取：
   - 优先查询 LLM 缓存
   - 缓存未命中 → 调用 LLM 根据元数据 Schema 提取结构化元数据
   - 将结果写入 LLM 缓存
4. 合并所有 chunk 的元数据：
   - 逐步合并每个 chunk 的元数据到文档级别
   - 获取文档已有的元数据并合并
   - 更新文档的元数据记录

**可能失败**：LLM 调用失败 → 取消所有元数据生成任务，抛出异常

---

#### 6.4 自动标签分类（当 `tag_kb_ids` 非空时）
1. 获取目标知识库的标签体系：
   - 优先从缓存获取
   - 缓存未命中 → 从检索引擎查询标签（上限 1000 条）
   - 将标签写入缓存
2. 创建 Chat 模型调用实例
3. 对每个 chunk 进行标签匹配，分两种路径：
   - **检索匹配路径**：通过检索引擎直接匹配标签的 chunk，直接标记
   - **LLM 分类路径**：检索无法匹配的 chunk，使用 LLM 进行分类
     - 优先查询 LLM 缓存
     - 缓存未命中 → 使用 few-shot 示例（从已标记的 chunk 中随机选取 2 个）辅助分类
     - 将结果写入 LLM 缓存
4. 每个 chunk 处理前检查任务取消状态

**可能失败**：LLM 调用失败 → 取消所有标签分类任务，抛出异常

---

### 第七步：向量嵌入（embedding）
1. **准备嵌入文本**：
   - 对每个 chunk 提取用于嵌入的文本内容
   - 优先使用 `question_kwd`（问题关键词）
   - 如果无问题关键词，使用 `content_with_weight`（带权重文本）
   - 去除 HTML 表格标签，避免干扰嵌入
   - 空文本替换为"None"
2. **生成文件名嵌入向量**：
   - 对文档名称生成嵌入向量（所有 chunk 共享同一个文件名向量）
   - 通过 tile 操作复制为与 chunk 数量相同的矩阵
3. **分批内容嵌入**：
   - 按 `EMBEDDING_BATCH_SIZE` 分批处理
   - 每批文本截断到模型最大长度（max_length - 10）
   - 调用嵌入模型批量编码
   - 累计 token 消耗量
   - 更新嵌入进度（70%~90% 区间）
4. **加权混合向量**：
   - 读取 `filename_embd_weight` 配置（默认 0.1）
   - 最终向量 = 文件名权重 x 文件名向量 + (1 - 文件名权重) x 内容向量
5. **写入 chunk**：
   - 将最终向量写入每个 chunk 的 `q_{维度}_vec` 字段

**可能失败**：嵌入模型调用失败 → 记录"生成嵌入错误"，终止任务

---

### 第八步：可选 TOC 生成（后台线程）
1. 判断条件：解析器为 `naive` 且 `parser_config` 中 `toc_extraction = true`
2. 在后台线程中执行 TOC 生成：
   - 获取 Chat 模型配置并创建调用实例
   - 按页码和坐标排序所有 chunk
   - 调用 LLM 从 chunk 文本中生成目录结构
   - 将目录项映射到对应的 chunk ID 范围
   - 生成一个特殊的 TOC chunk（标记为 `toc_kwd`，`available_int = 0`）
3. TOC chunk 的 ID 通过 xxhash64 哈希生成
4. 主流程继续执行，不等待 TOC 生成完成

---

### 第九步：插入 chunks 到文档存储
1. **处理母 chunk（mother chunk）**：
   - 遍历所有 chunk，检查是否包含 `mom` 或 `mom_with_weight` 字段
   - 为每个母 chunk 生成唯一 ID（基于内容哈希）
   - 建立普通 chunk 与母 chunk 的关联（`mom_id` 字段）
   - 母 chunk 仅保留核心字段（ID、内容、文档 ID、知识库 ID 等）
   - 设置母 chunk 的 `available_int = 0`（标记为不可用/仅做上下文引用）
2. **分批插入母 chunk**：
   - 按 `DOC_BULK_SIZE` 分批
   - 每批插入后检查任务取消状态
   - 已取消 → 返回 False，终止插入
3. **分批插入普通 chunk**：
   - 按 `DOC_BULK_SIZE` 分批
   - 每批插入后：
     - 检查任务取消状态（已取消 → 返回 False）
     - 更新进度（80%~90% 区间）
     - 检查存储返回结果（有错误 → 抛出异常）
     - **检查点/断点续传**：将已插入的 chunk ID 列表更新到任务记录
       - 如果任务记录已不存在 → 回滚：删除已插入的 chunks 和图片，终止流程
4. 返回插入结果（True = 成功，False = 被中断）

**可能失败**：
- 文档存储写入错误 → 返回"插入 chunk 错误"
- 任务被取消 → 终止插入
- 任务记录不存在 → 回滚已插入数据

---

### 第十步：更新统计数据
1. 更新文档级统计：
   - 文档的 `chunk_num` 增加本次解析的 chunk 数量
   - 文档的 `token_num` 增加本次嵌入消耗的 token 数量
2. 更新知识库级统计：
   - 知识库总 chunk 数增加
   - 知识库总 token 数增加

---

### 第十一步：TOC 结果入库（如果第八步生成了 TOC）
1. 等待后台 TOC 线程完成
2. 如果生成了有效的 TOC chunk：
   - 检查任务取消状态
   - 将 TOC chunk 插入文档存储
   - 文档的 `chunk_num` 额外增加 1（TOC chunk）

---

### 第十二步：任务完成
1. 检查任务是否被取消（最终检查）
2. 如果未被取消：
   - 设置任务进度为 100%（完成）
   - 记录总耗时
   - 记录完成日志（文档名、页码范围、chunk 数、token 数、总耗时）
3. 如果被取消 → 进入第十三步清理流程

---

### 第十三步：取消清理（finally 块，任务被取消时执行）
1. 检查文档存储中对应的索引是否存在
2. 如果索引存在：
   - 删除该文档的所有已插入 chunk 数据（按 `doc_id` 匹配）
   - 防止残留脏数据影响后续查询
3. 记录清理异常（如有），但不影响取消流程的完成

**可能失败**：清理操作本身失败 → 记录异常日志，不影响取消确认

---

## 业务规则总结

### 任务参数优先级规则
- LLM 模型 ID 优先级：`parser_config.llm_id` > 任务级 `llm_id`
- 知识库级配置优先于文档级配置
- 嵌入模型 ID 为空时，使用租户默认模型

### 取消检查规则
- 在每个关键步骤前后均检查 Redis 取消标志
- 取消后立即停止当前操作
- 取消后清理已写入的数据（删除 chunk、图片）
- 取消不算失败，计入"已完成"统计

### 分块规则
- 文件大小超出系统限制时直接拒绝
- 每种文件类型对应专属解析器
- chunk ID 基于 content_with_weight 和 doc_id 的 xxhash64 哈希生成
- 母 chunk（mother chunk）用于层级关联，标记为不可用

### 向量嵌入规则
- 嵌入文本优先使用问题关键词，其次使用原始内容
- 文件名嵌入与内容嵌入加权混合，默认权重比为 0.1:0.9
- 分批嵌入，受嵌入并发信号量控制
- 自动去除 HTML 表格标签

### 断点续传规则
- 每批 chunk 插入后更新任务的 `chunk_ids` 字段
- 如果任务记录已消失，自动回滚已插入数据
- 确保 chunk 数据与任务记录的一致性

### LLM 增强规则
- 所有关键词、问题、元数据生成均使用 LLM 缓存
- 缓存命中则跳过 LLM 调用，节省 token 消耗
- 并发执行 LLM 增强，受 `chat_limiter` 并发控制
- 每个增强步骤前检查任务取消状态

## 输入输出

### 输入（任务对象）
| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| id | string | 是 | 任务唯一 ID |
| doc_id | string | 是 | 文档 ID |
| kb_id | string | 是 | 知识库 ID |
| tenant_id | string | 是 | 租户 ID |
| embd_id | string | 否 | 嵌入模型 ID（空则用租户默认） |
| llm_id | string | 否 | LLM 模型 ID |
| name | string | 是 | 文档名称 |
| parser_id | string | 是 | 解析器类型 |
| parser_config | object | 是 | 解析器配置 |
| kb_parser_config | object | 是 | 知识库级解析器配置 |
| from_page | number | 否 | 起始页码 |
| to_page | number | 否 | 结束页码 |
| language | string | 否 | 文档语言 |
| size | number | 是 | 文件大小（字节） |
| location | string | 是 | 存储路径 |
| pagerank | number | 否 | 页面权重 |

### 输出
| 字段 | 类型 | 说明 |
|------|------|------|
| 任务进度 | number | 0~1 为正常进度，-1 为错误 |
| 进度消息 | string | 带时间戳和页码范围的状态消息 |
| chunk 列表 | array | 写入文档存储的 chunk 数据 |

### chunk 结构
| 字段 | 说明 |
|------|------|
| id | chunk 唯一 ID（xxhash64 哈希） |
| doc_id | 所属文档 ID |
| kb_id | 所属知识库 ID |
| content_with_weight | 带权重文本内容 |
| q_{dim}_vec | 嵌入向量 |
| important_kwd | 关键词列表（如有） |
| question_kwd | 问题列表（如有） |
| img_id | 图片 ID（如有） |
| mom_id | 母 chunk ID（如有） |
| create_time | 创建时间 |
| page_num_int | 页码信息 |
| position_int | 位置坐标 |

## 错误处理

| 错误场景 | 处理方式 |
|----------|----------|
| 文件大小超限 | 设置错误进度，返回空 chunk 列表 |
| MinIO 文件获取超时 | 记录超时错误，终止任务 |
| MinIO 文件不存在 | 记录文件未找到错误，终止任务 |
| 嵌入模型绑定失败 | 记录绑定失败错误，终止任务 |
| 文档分块异常 | 记录内部错误，终止任务 |
| MinIO 图片上传失败 | 取消所有上传任务，终止流程 |
| LLM 调用失败（关键词/问题/元数据/标签） | 取消所有并发任务，终止流程 |
| 向量嵌入失败 | 记录嵌入错误，终止任务 |
| 文档存储插入失败 | 记录插入错误，终止任务 |
| 任务被取消 | 清理已插入数据，正常结束 |
| 任务记录消失 | 回滚已插入的 chunk 和图片，终止流程 |

---

## 注意事项

1. **超时保护**：整个任务最长 3 小时（通过 `@timeout(3600)` 装饰器控制）
2. **并发控制**：分块构建、向量嵌入、MinIO 操作均有独立的并发信号量限制
3. **LLM 缓存**：所有 LLM 增强操作均使用缓存机制，避免重复调用
4. **取消安全**：在每个关键节点检查取消标志，确保可及时中断
5. **断点续传**：每批 chunk 插入后更新检查点，任务失败后可从上次位置恢复
6. **TOC 异步生成**：目录提取在后台线程执行，不阻塞主流程
7. **向量加权**：文件名嵌入与内容嵌入按配置权重混合，影响检索相关性
8. **母 chunk 机制**：部分解析器会生成包含完整上下文的母 chunk，用于层级关联
9. **标签分流处理**：标签分类时优先通过检索匹配，匹配不到的才调用 LLM

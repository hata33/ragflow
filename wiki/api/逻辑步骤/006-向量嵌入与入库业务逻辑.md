# 向量嵌入与入库 - 业务逻辑步骤

## 概述
- **所属流程**: 文档解析后台任务（task_executor）
- **触发时机**: build_chunks（分块）完成之后，由 do_handle_task 调用
- **功能**: 将 chunk 文本转换为向量并写入文档存储（Elasticsearch 或 Infinity）
- **前置条件**: chunk 列表已构建完成，嵌入模型已绑定

---

## Part 1：embedding() 向量嵌入

### 第一步：准备嵌入文本

对每个 chunk 分别准备两组文本：

1. **文件名列表（tts）**：取每个 chunk 的 `docnm_kwd` 字段，若无则使用默认值 "Title"
2. **内容列表（cnts）**：按以下优先级选择嵌入文本：
   - 优先使用 `question_kwd`（LLM 生成的问题关键词），将列表拼接为换行分隔的字符串
   - 若 `question_kwd` 为空，则退回使用 `content_with_weight`（原始加权内容）
3. **HTML 清洗**：去除文本中的 HTML 表格标签（table、td、caption、tr、th 及其属性），替换为空格
4. **空值兜底**：清洗后若文本为空字符串，替换为 "None"

---

### 第二步：生成文件名嵌入向量

1. 取文件名列表的第一个元素，调用嵌入模型编码生成单个向量
2. 统计本次编码消耗的 token 数
3. 将该单一向量按 chunk 数量进行 **tile（平铺复制）**，使每个 chunk 对应一个相同的文件名向量

**前提条件**：文件名列表长度必须等于内容列表长度，否则跳过文件名嵌入

---

### 第三步：批量内容嵌入

将所有 chunk 的内容文本分批送入嵌入模型：

1. **分批策略**：按 `EMBEDDING_BATCH_SIZE`（默认 16）将内容列表拆分为多个批次
2. **并发控制**：每批编码前需获取 `embed_limiter` 信号量，限制同时执行的嵌入任务数
3. **文本截断**：每条文本在编码前截断到模型最大长度减 10（`max_length - 10`），预留安全余量
4. **向量拼接**：将每批生成的向量依次拼接（concatenate）为完整的向量矩阵
5. **进度更新**：每完成一个批次，按比例更新嵌入进度（0.7 ~ 0.9 区间）

**可能失败**：嵌入模型调用失败（网络超时、模型不可用、token 超限） → 抛出异常，任务失败

---

### 第四步：加权合并向量

1. 读取 `parser_config` 中的 `filename_embd_weight`（文件名嵌入权重，默认 0.1 即 10%）
2. 若权重值为空或 0，使用默认值 0.1
3. 计算最终向量：`最终向量 = 文件名权重 * 文件名向量 + (1 - 文件名权重) * 内容向量`
   - 默认比例：10% 文件名 + 90% 内容
4. 若文件名向量与内容向量维度不匹配或为空，直接使用内容向量

---

### 第五步：写入向量到 chunks

1. 遍历每个 chunk，将对应的混合向量以列表形式写入
2. 字段命名规则：`q_{向量维度}_vec`（例如 `q_1024_vec`）
3. 记录向量维度（vector_size），用于后续索引操作
4. 断言向量数量与 chunk 数量一致

**返回值**：(token 消耗数, 向量维度)

---

## Part 2：insert_chunks() 入库

### 第六步：处理母 chunk（mother chunk）

母 chunk 是包含完整上下文信息的特殊 chunk，用于层级关联。

1. 遍历所有 chunk，提取 `mom` 或 `mom_with_weight` 字段的值
2. 若该字段为空，跳过该 chunk
3. 对母内容计算 **xxhash64** 哈希值作为唯一 ID
4. 将母 ID（`mom_id`）写入子 chunk，建立关联关系
5. 对母内容进行**去重**：同一 ID 的母 chunk 只保留一个
6. 构建母 chunk 对象（深拷贝子 chunk），仅保留核心字段：
   - id、content_with_weight、doc_id、docnm_kwd、kb_id
   - available_int（设为 0）、position_int、create_timestamp_flt、page_num_int、top_int
7. 删除所有非核心字段（包括向量、关键词、图片等）

---

### 第七步：批量插入母 chunk

1. 按 `DOC_BULK_SIZE`（默认 4）将母 chunk 分批
2. 每批调用文档存储连接器的 `insert` 方法写入
3. **每批插入后检查取消状态**：若任务已被取消，设置错误进度并返回 False

**可能失败**：任务被取消 → 返回 False，中止插入

---

### 第八步：批量插入普通 chunk

逐批将普通 chunk 写入文档存储，每批处理后执行以下检查：

#### 8.1 取消检查
每批插入后立即检查任务是否被取消。若已取消，设置错误进度并返回 False。

#### 8.2 进度更新
每处理 128 的整数倍批次时更新进度（0.8 ~ 0.9 区间），避免频繁写库。

#### 8.3 错误检查
检查文档存储的返回结果。若返回非空错误信息，设置错误进度并抛出异常。

#### 8.4 断点续传（checkpoint）
每批插入成功后，将当前所有已插入的 chunk ID 拼接为空格分隔的字符串，更新到任务的 `chunk_ids` 字段。
- **用途**：任务中断后可通过 chunk_ids 知道哪些数据已写入，支持断点续传

#### 8.5 回滚处理（任务被删除）
若更新 chunk_ids 时发现任务已不存在（DoesNotExist），执行回滚：
1. 从文档存储中删除所有已插入的 chunk（按 ID 批量删除）
2. 从对象存储（MinIO）中删除每个 chunk 对应的图片文件
3. 设置错误进度消息并返回 False

**可能失败**：文档存储写入失败 → 抛出异常；任务不存在 → 自动回滚已插入数据

---

### 第九步：返回结果

- 所有 chunk 插入成功 → 返回 True
- 任务被取消或任务不存在 → 返回 False

---

## 进度分布规则

整个文档解析任务的进度区间划分如下：

| 进度区间 | 阶段 | 说明 |
|---------|------|------|
| 0.0 ~ 0.1 | build_chunks 预处理 | 文件获取、解析器初始化 |
| 0.1 ~ 0.5 | chunker.chunk | 文档解析与分块 |
| 0.5 ~ 0.7 | LLM 增强 | 关键词提取、问题生成、元数据生成、标签分类 |
| 0.7 ~ 0.9 | embedding | 向量嵌入（第三步中按批次线性推进） |
| 0.8 ~ 0.9 | insert_chunks | chunk 入库（第八步中按批次推进） |
| 0.9 ~ 1.0 | 统计更新 + TOC | 更新文档统计信息，插入目录 chunk |
| 1.0 | 完成 | 任务结束 |

**注意**：embedding 和 insert_chunks 的进度区间存在重叠（0.8~0.9），因为两者在同一任务中顺序执行。

## 输入输出

### embedding() 输入
| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| docs | list[dict] | 是 | chunk 字典列表，每个需包含 content_with_weight 和 docnm_kwd |
| mdl | LLMBundle | 是 | 嵌入模型实例 |
| parser_config | dict | 否 | 解析器配置，含 filename_embd_weight 等 |
| callback | function | 否 | 进度回调函数 |

### embedding() 输出
| 字段 | 类型 | 说明 |
|------|------|------|
| token_count | int | 嵌入过程消耗的总 token 数 |
| vector_size | int | 生成的向量维度 |

### insert_chunks() 输入
| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| task_id | string | 是 | 任务 ID |
| task_tenant_id | string | 是 | 租户 ID |
| task_dataset_id | string | 是 | 知识库 ID |
| chunks | list[dict] | 是 | 包含向量的 chunk 字典列表 |
| progress_callback | function | 是 | 进度回调函数 |

### insert_chunks() 输出
| 字段 | 类型 | 说明 |
|------|------|------|
| result | bool | True=插入成功，False=被中断或取消 |

## 错误处理

| 错误场景 | 处理方式 |
|----------|----------|
| 嵌入模型调用失败 | 抛出异常，任务标记为失败，记录错误信息 |
| 文件名向量与内容向量维度不匹配 | 跳过文件名混合，直接使用内容向量 |
| 任务被取消（embedding 阶段） | 抛出 TaskCanceledException，上层清理 |
| 任务被取消（insert 阶段） | 返回 False，上层执行清理 |
| 文档存储写入失败 | 抛出异常，任务标记为失败 |
| 任务在插入过程中被删除（DoesNotExist） | 自动回滚：删除已写入的 chunk 和图片，返回 False |
| chunk 数量与向量数量不一致 | 触发断言错误，任务失败 |
| 图片删除失败 | 记录日志并抛出异常 |

---

## 取消清理机制

当任务在 embedding 或 insert_chunks 过程中被取消时，由上层 `do_handle_task` 的 finally 块执行清理：

1. 检查文档存储中对应的索引是否存在
2. 若存在，按 `doc_id` 删除该文档的所有 chunk 数据
3. 清理失败仅记录日志，不影响取消流程完成

---

## 业务规则总结

### 向量混合规则
- 文件名向量所有 chunk 共享同一份（tile 平铺）
- 最终向量 = 文件名权重 * 文件名向量 + (1 - 文件名权重) * 内容向量
- 默认文件名权重 0.1（10%），可通过 parser_config 调整

### 批量处理规则
- 嵌入批次大小：`EMBEDDING_BATCH_SIZE`（默认 16，可通过环境变量配置）
- 入库批次大小：`DOC_BULK_SIZE`（默认 4，可通过环境变量配置）
- 进度更新频率：入库阶段每 128 批次更新一次

### 母 chunk 规则
- 母 chunk 仅保留核心字段，不含向量和关键词等扩展信息
- 母 chunk 的 available_int 设为 0（标记为不可直接检索）
- 同一内容的母 chunk 自动去重（基于 xxhash64）

### 断点续传规则
- 每批 chunk 入库成功后，将 chunk_ids 更新到任务记录
- 任务恢复时可通过 chunk_ids 确定已入库的数据量

### 并发控制规则
- `embed_limiter`：限制同时执行的嵌入批次数（默认等于 MAX_CONCURRENT_CHUNK_BUILDERS）
- 嵌入操作使用线程池执行（`thread_pool_exec`），不阻塞异步事件循环

---

## 注意事项

1. **向量字段命名**：格式为 `q_{维度}_vec`，维度由嵌入模型决定，不同模型维度不同
2. **文本截断**：内容文本在嵌入前截断到 `max_length - 10`，预留 10 token 安全边界
3. **HTML 清洗**：仅清洗表格相关标签，其他 HTML 标签保留
4. **母 chunk 去重**：基于内容的 xxhash64 哈希去重，同一母内容只会入库一次
5. **取消安全**：取消操作在每批处理后检查，不会中断正在执行的批次
6. **图片清理**：任务被删除时，会同步清理对象存储中 chunk 关联的图片
7. **进度区间重叠**：embedding（0.7~0.9）与 insert_chunks（0.8~0.9）的进度区间存在重叠，因为两者顺序执行

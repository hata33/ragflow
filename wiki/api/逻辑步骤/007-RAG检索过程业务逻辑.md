# RAG检索过程 - 业务逻辑步骤

## 接口信息
- **功能**: 基于知识库文档进行检索增强生成（RAG），返回带引用的智能回答
- **两种模式**: 对话聊天（async_chat）、快捷提问（async_ask）

---

## 两种模式概述

| 模式 | 入口 | 是否有历史 | 是否自建模型 | 适用场景 |
|------|------|-----------|-------------|---------|
| 对话聊天（async_chat） | 对话接口 | 有多轮历史 | 由对话配置提供 | 多轮知识库问答 |
| 快捷提问（async_ask） | 快捷提问接口 | 无历史 | 自行初始化 | 单次快速查询 |

---

## 模式一：对话聊天（async_chat）

### 第一步：预检查 —— 纯LLM聊天判断
1. 检查当前对话是否关联了知识库
2. 检查对话是否配置了外部搜索（如 Tavily）
3. 如果**既没有知识库，也没有外部搜索**：
   - 走纯 LLM 聊天路径
   - 直接调用对话模型生成回答，跳过所有检索步骤
   - 无引用信息，无检索增强

**可能失败**：对话模型调用失败 → 返回错误信息

---

### 第二步：模型绑定
1. 获取对话关联的所有知识库对象列表
2. 从知识库配置中获取嵌入模型（Embedding Model）
3. 从知识库配置中获取重排序模型（Rerank Model），如果未配置则标记为"无重排序"
4. 获取对话配置的聊天模型（Chat Model）
5. **关键校验**：验证所有知识库是否使用相同的嵌入模型
   - 不一致 → 返回"知识库嵌入模型不一致"错误

**可能失败**：模型配置缺失或嵌入模型不一致 → 返回配置错误

---

### 第三步：问题准备

#### 3.1 提取历史消息
1. 从对话历史中提取最近 3 条用户消息
2. 将这些消息作为多轮对话上下文

#### 3.2 多轮对话精炼（可选）
1. 判断是否开启了多轮对话精炼（配置项控制）
2. 如果开启：
   - 将最近 3 条用户消息和对话历史一起发送给 LLM
   - LLM 将多轮对话压缩为一个独立的问题
   - 用压缩后的问题替代原始问题进行检索
3. 如果未开启：
   - 使用原始问题直接检索

**可能失败**：LLM 精炼调用失败 → 回退使用原始问题

---

#### 3.3 跨语言翻译（可选）
1. 判断是否开启了跨语言翻译（配置项控制）
2. 如果开启：
   - 将用户问题翻译为知识库文档的主要语言
   - 用翻译后的问题进行检索，以提高跨语言检索效果

**可能失败**：翻译调用失败 → 使用原始问题

---

#### 3.4 元数据过滤（可选）
1. 判断是否配置了元数据过滤条件
2. 如果配置了：
   - 解析过滤条件，构建过滤规则
   - 后续检索时将过滤规则附加到搜索请求中

---

#### 3.5 关键词提取（可选）
1. 判断是否开启了自动关键词提取
2. 如果开启：
   - 使用 LLM 从问题中提取关键词
   - 将关键词用于全文检索的权重增强

**可能失败**：关键词提取失败 → 不使用关键词增强，继续检索

---

### 第四步：检索策略选择

根据配置和条件，选择以下三种检索策略之一：

| 策略 | 触发条件 | 特点 |
|------|---------|------|
| SQL 检索 | 知识库配置了 field_map（结构化字段映射） | 将自然语言转为 SQL 查询 |
| DeepResearch | 对话配置了 DeepResearch 模式 | 自主多轮检索，深度研究 |
| 标准检索 | 默认策略 | 混合搜索 + 重排序 |

#### 分支 A：SQL 检索
1. 尝试将自然语言问题转换为 SQL 查询
2. 执行 SQL 查询获取结果
3. 如果 SQL 转换或执行失败 → **回退到标准检索**

**可能失败**：SQL 转换失败或查询执行异常 → 自动回退到标准检索

---

#### 分支 B：DeepResearch 模式
1. 进入自主多轮检索循环
2. 每轮根据当前已有信息决定下一步检索策略
3. 循环直到信息充分或达到最大轮次限制
4. 汇总所有轮次的检索结果

---

#### 分支 C：标准检索（核心路径）

##### 第四步之一：计算初始获取量（RERANK_LIMIT）
1. 根据配置的 topk 值和相似度阈值，计算初始获取数量
2. RERANK_LIMIT = topk * 扩展系数
3. 目的：先多取一些结果，经过重排序后再筛选出最优的 topk 条

---

##### 第四步之二：构建搜索请求
1. 组装搜索请求参数：
   - 知识库 ID 列表
   - 文档 ID 列表（如果限定）
   - 页码和每页大小
   - 检索问题
   - 相似度阈值
   - topk 数量
   - 元数据过滤条件（如有）
   - 关键词（如有）

---

##### 第四步之三：执行混合搜索
1. **全文检索（BM25）**：
   - 对问题进行分词
   - 在知识库 chunks 中执行全文匹配
   - 计算 BM25 相关性得分
2. **向量检索（Vector Similarity）**：
   - 将问题通过嵌入模型转为向量
   - 在向量存储中搜索相似 chunks
   - 计算余弦相似度得分
3. **加权融合**：
   - 将全文检索和向量检索的结果合并
   - 按权重加权计算综合得分
   - 权重比例由知识库配置决定

**可能失败**：向量存储不可用 → 返回检索服务异常

---

##### 第四步之四：重排序
1. 判断是否配置了重排序模型：
   - **有重排序模型**：
     - 将初筛后的 chunks 文本和问题一起送入重排序模型
     - 模型输出每个 chunk 与问题的相关性得分
   - **无重排序模型**：
     - 使用本地混合相似度计算（结合向量相似度和全文匹配度）
     - 不依赖外部模型，计算综合得分
2. 按重排序得分重新排列结果

---

##### 第四步之五：相似度过滤
1. 根据配置的相似度阈值，过滤掉低于阈值的结果
2. 只保留相关性足够高的 chunks

---

##### 第四步之六：排序与分页
1. 将过滤后的结果按得分降序排列
2. 根据请求的页码和每页大小进行分页截取
3. 返回当前页的 chunks 列表

---

### 第五步：检索后增强

#### 5.1 目录增强（TOC Enhancement，可选）
1. 判断是否开启了目录增强（配置项控制）
2. 如果开启：
   - 获取文档的目录结构（Table of Contents）
   - 将目录信息和检索问题一起发送给 LLM
   - LLM 从目录中选出最相关的章节
   - 将相关章节的内容补充到检索结果中

**可能失败**：LLM 调用失败 → 跳过目录增强，使用原始检索结果

---

#### 5.2 父子块检索
1. 判断知识库是否开启了父子块（Parent-Child Chunk）模式
2. 如果开启：
   - 检索命中的是子块（child chunk）
   - 根据子块的关联关系，获取其父块（parent chunk）
   - 用父块的完整内容替换子块
   - 目的：提供更完整的上下文，避免信息碎片化

---

#### 5.3 外部搜索（Tavily，可选）
1. 判断是否配置了 Tavily 外部搜索
2. 如果配置了：
   - 将问题发送给 Tavily 搜索引擎
   - 获取外部搜索结果
   - 将外部结果与知识库检索结果合并

**可能失败**：Tavily 服务不可用 → 跳过外部搜索，仅使用知识库结果

---

#### 5.4 GraphRAG 知识图谱检索（可选）
1. 判断是否开启了 GraphRAG 模式
2. 如果开启，进入 GraphRAG 检索子流程（详见下方"GraphRAG 检索子流程"）
3. 将知识图谱检索结果与标准检索结果合并

---

### 第六步：Prompt 构造
1. 将检索到的 chunks 格式化为结构化文本：
   - 每个 chunk 标注来源文档名、页码等引用信息
   - 按相关性得分排列
2. 组装完整的 Prompt：
   - 系统提示词（对话配置的 system prompt）
   - 检索到的知识内容（格式化后的 chunks）
   - 用户问题
   - 对话历史（如有）
3. 检查 Prompt 总长度是否超过模型的最大 token 限制
4. 如果超限，按优先级截断（优先保留系统提示词和问题，截断知识内容）

---

### 第七步：LLM 生成
1. 将构造好的 Prompt 发送给对话模型
2. 以流式（streaming）方式逐步生成回答
3. 在生成过程中：
   - 实时将生成的文本片段推送给前端
   - 跟踪模型输出的引用标记
4. 生成完成后：
   - 将引用标记映射回原始 chunk 来源
   - 组装引用信息列表（文档名、页码、相似度等）
   - 将完整回答和引用信息持久化到对话记录

**可能失败**：LLM 生成超时或调用失败 → 返回已生成的部分内容 + 错误提示

---

## 模式二：快捷提问（async_ask）

### 第一步：自建模型
1. 快捷提问不依赖预设对话，需自行初始化模型
2. 从请求参数中获取知识库 ID
3. 加载知识库的嵌入模型、重排序模型
4. 加载用户配置的对话模型

**可能失败**：模型配置缺失 → 返回配置错误

---

### 第二步：知识图谱模式检测
1. 检查知识库是否开启了 GraphRAG
2. 如果开启，标记后续需要执行知识图谱检索

---

### 第三步：执行检索
1. 没有对话历史，直接使用原始问题
2. 不执行多轮精炼和翻译
3. 走标准检索流程（同模式一的第四步、第五步）

---

### 第四步：生成回答
1. 构造 Prompt（同模式一第六步）
2. 调用 LLM 流式生成回答
3. 返回回答和引用信息

---

## GraphRAG 检索子流程

当知识库开启了知识图谱模式时，除了标准向量检索外，还会执行以下子流程：

### 第一步：查询改写
1. 将用户问题发送给 LLM
2. LLM 从问题中提取：
   - 实体类型（如"人物"、"组织"、"地点"等）
   - 具体实体名称（如"张三"、"微软"等）
3. 输出结构化的查询信息

**可能失败**：LLM 提取失败 → 跳过 GraphRAG 检索，仅使用标准检索

---

### 第二步：实体检索
1. **关键词向量搜索**：
   - 将提取的实体名称转为向量
   - 在知识图谱的实体索引中进行向量搜索
   - 返回相似度最高的实体
2. **类型 PageRank 搜索**：
   - 根据提取的实体类型
   - 在知识图谱中按 PageRank 值排序
   - 返回该类型下影响力最高的实体
3. 合并两种搜索结果，去重

---

### 第三步：关系检索
1. **文本向量搜索**：
   - 将问题转为向量
   - 在知识图谱的关系索引中进行向量搜索
   - 返回最相关的关系三元组
2. **N-hop 路径检索**：
   - 以检索到的实体为起点
   - 在知识图谱中进行 N 跳遍历
   - 发现实体之间的多跳关联路径
3. 合并关系搜索结果，去重

---

### 第四步：得分融合
1. **实体得分计算**：
   - 得分 = 向量相似度 x PageRank 值
   - 同时考虑语义相关性和图结构重要性
2. **关系得分计算**：
   - 得分 = 向量相似度 x PageRank 值 x 类型因子
   - 类型因子根据关系类型的重要性加权

---

### 第五步：排序与截断
1. 实体结果按得分降序排列，取 Top 6
2. 关系结果按得分降序排列，取 Top 6
3. 受 max_token 限制，如果文本总量超限则进一步截断

---

### 第六步：社区报告检索
1. 获取知识图谱中的社区（Community）信息
2. 社区是基于图聚类算法划分的实体群组
3. 每个社区有一份摘要报告
4. 根据检索到的实体和关系，找到相关社区
5. 获取相关社区的摘要报告
6. 将社区报告内容加入最终的检索结果

---

## 检索策略规则

| 条件 | 策略 | 说明 |
|------|------|------|
| 知识库有 field_map 配置 | SQL 检索优先 | 结构化数据优先使用 SQL 查询 |
| SQL 检索失败 | 回退到标准检索 | 保证检索的可用性 |
| 配置了 DeepResearch 模式 | DeepResearch | 自主多轮深度检索 |
| 默认情况 | 标准混合检索 | BM25 + 向量 + 重排序 |
| 知识库开启 GraphRAG | 附加知识图谱检索 | 与标准检索并行执行 |

---

## 关键配置参数

| 参数 | 说明 | 默认值 | 影响 |
|------|------|--------|------|
| similarity_threshold | 相似度阈值 | 0.2 | 低于此分数的 chunks 被过滤 |
| topk | 返回的最大 chunk 数量 | 6 | 控制注入 Prompt 的知识量 |
| rerank_id | 重排序模型 ID | 无 | 决定是否使用模型重排序 |
| keyword | 是否启用关键词提取 | false | 开启后增强全文检索精度 |
| cross_languages | 是否启用跨语言翻译 | false | 开启后支持跨语言检索 |
| multi_turn_refine | 是否启用多轮精炼 | false | 开启后压缩多轮为单问题 |
| toc_enable | 是否启用目录增强 | false | 开启后利用文档 TOC 补充上下文 |
| tavily_api_key | Tavily 外部搜索密钥 | 无 | 配置后启用外部搜索 |
| graphrag_enable | 是否启用知识图谱检索 | false | 开启后附加 GraphRAG 检索 |
| max_tokens | Prompt 最大 token 数 | 根据模型而定 | 超限时截断知识内容 |
| hybrid_search_weight | 混合搜索中向量检索权重 | 0.7 | 向量与全文的权重比例 |

---

## 混合搜索融合规则

### 得分归一化
1. 全文检索（BM25）和向量检索的原始得分范围不同
2. 使用 Min-Max 归一化将两种得分统一到 [0, 1] 区间
3. 归一化公式：`归一化得分 = (原始得分 - 最小得分) / (最大得分 - 最小得分)`

### 加权融合
1. 归一化后的综合得分 = 向量权重 x 向量得分 + (1 - 向量权重) x 全文得分
2. 默认向量权重 0.7，全文权重 0.3
3. 权重可通过知识库配置调整

### 融合去重
1. 同一个 chunk 可能同时出现在向量检索和全文检索结果中
2. 对于重复出现的 chunk，取两种检索方式中较高的得分
3. 然后按加权公式计算综合得分

---

## 错误处理

| 错误场景 | 处理方式 | 用户感知 |
|----------|---------|---------|
| 知识库嵌入模型不一致 | 拒绝检索 | 返回"知识库嵌入模型不一致"错误 |
| 向量存储不可用 | 检索失败 | 返回检索服务异常 |
| 重排序模型调用失败 | 使用本地混合相似度替代 | 结果质量可能下降，但不会中断 |
| 多轮精炼 LLM 失败 | 使用原始问题检索 | 检索精度可能下降 |
| 跨语言翻译失败 | 使用原始问题检索 | 跨语言检索效果可能下降 |
| 关键词提取失败 | 不使用关键词增强 | 全文检索精度可能下降 |
| 目录增强 LLM 失败 | 跳过目录增强 | 上下文完整性可能下降 |
| Tavily 外部搜索不可用 | 跳过外部搜索 | 仅使用知识库内部结果 |
| GraphRAG 检索失败 | 跳过知识图谱检索 | 仅使用标准检索结果 |
| LLM 生成超时 | 返回已生成的部分内容 | 回答可能不完整 |
| SQL 检索失败 | 自动回退到标准检索 | 用户无感知 |
| Prompt 超过最大 token | 截断知识内容 | 可能丢失部分检索结果 |
| 纯 LLM 模式下模型调用失败 | 返回错误信息 | 无法获得回答 |

---

## 注意事项

1. **两种检索路径**：对话聊天和快捷提问共享核心检索逻辑，区别在于是否有对话历史和模型初始化方式
2. **混合搜索**：标准检索同时使用 BM25 全文检索和向量相似度检索，融合后效果优于单一检索
3. **重排序保底**：即使重排序模型不可用，也有本地相似度计算作为降级方案
4. **多级可选增强**：关键词提取、多轮精炼、跨语言翻译、目录增强、外部搜索、GraphRAG 均为可选，全部有降级方案
5. **SQL 回退机制**：SQL 检索失败时自动回退到标准检索，保证可用性
6. **流式响应**：LLM 生成采用流式输出，前端可以实时显示生成过程
7. **引用追踪**：每个检索结果都记录来源，生成回答时自动插入引用标记
8. **父子块上下文**：开启父子块模式后，用更大的父块替换小子块，提供更完整的上下文
9. **GraphRAG 并行**：知识图谱检索与标准检索并行执行，最后合并结果
10. **Token 限制**：所有内容最终受模型 max_tokens 限制，超限时按优先级截断

# 文档解析接口 - 业务逻辑步骤

## 接口信息
- **路由**: `POST /api/v1/document/run`
- **功能**: 启动或取消文档解析任务
- **认证**: 需要用户登录

---

## 业务逻辑流程

### 第一步：用户身份认证
1. 验证用户是否已登录
2. 从请求头中获取认证令牌（JWT 或 API Token）
3. 解析令牌获取用户信息
4. 验证用户身份有效性

**可能失败**：用户未登录或令牌无效 → 返回认证失败

---

### 第二步：请求参数验证
1. 获取请求 JSON 数据
2. 验证必需参数 `doc_ids`（文档 ID 列表）是否存在
   - 不存在 → 返回参数错误
3. 验证必需参数 `run`（运行状态）是否存在
   - 不存在 → 返回参数错误
4. 获取可选参数：
   - `delete`：是否删除已有解析结果（默认否）
   - `apply_kb`：是否应用知识库配置（默认否）

**可能失败**：参数缺失或不符合规范 → 返回参数错误

---

### 第三步：逐文档权限与状态处理

对 `doc_ids` 列表中的**每个文档**依次执行以下步骤（第三步至第十一步）：

#### 第四步：文档访问权限检查
1. 根据文档 ID 查询文档信息
2. 查询用户所属的租户列表
3. 验证文档所属租户是否在用户的租户列表中
4. 无权限则拒绝继续处理

**可能失败**：用户无权访问该文档 → 返回"无权限"错误

---

#### 第五步：获取文档所属租户
1. 通过文档 ID 关联查询其所属知识库
2. 通过知识库获取租户 ID
3. 租户不存在则报错

**可能失败**：租户信息查询失败 → 返回"租户未找到"错误

---

#### 第六步：获取文档完整信息
1. 根据文档 ID 从数据库获取文档记录
2. 获取文档的解析器类型、配置、运行状态等信息

**可能失败**：文档不存在 → 返回"文档未找到"错误

---

#### 第七步：处理取消操作（当 run=取消时）
1. 查询该文档关联的所有任务记录
2. 检查是否存在未完成的任务（进度 < 100%）
3. 如果文档状态为"运行中"或存在未完成任务：
   - 为每个任务在 Redis 中设置取消标志
   - 任务执行器会在后续检查中发现标志并停止执行
4. 如果文档未在运行且无未完成任务：
   - 返回"无法取消未运行的任务"错误

**可能失败**：文档未在运行状态 → 返回"无法取消"错误

---

#### 第八步：重新运行时的计数清理
当同时满足以下条件时执行：
- 请求中包含 `delete=true`
- `run` 状态为"运行中"
- 文档之前的状态为"已完成"

执行操作：
1. 获取文档当前的 token 数和 chunk 数
2. 从知识库的统计总量中扣减这些数值
3. 保证重新运行时知识库统计数据不会重复累加

---

#### 第九步：更新文档运行状态
1. 将文档的 `run` 字段设为请求中的目标状态
2. 将进度重置为 0
3. 如果是重新运行且请求删除旧结果：
   - 清空进度消息
   - 重置 chunk 数和 token 数

---

#### 第十步：删除已有解析结果（当 delete=true 时）
1. 删除该文档关联的所有任务记录
2. 构建索引名称（规则：`ragflow_{租户ID}`）
3. 从向量存储（Elasticsearch 或 Infinity）中删除该文档的所有 chunk 数据
   - 删除条件：文档 ID 匹配
   - 删除范围：指定索引 + 指定知识库

---

#### 第十一步：应用知识库配置（当 apply_kb=true 时）
1. 根据文档所属知识库 ID 获取知识库配置
2. 将知识库的以下配置同步到文档：
   - LLM 模型 ID
   - 元数据生成开关
   - 元数据 schema 配置
3. 更新文档的解析器配置

**可能失败**：知识库不存在 → 返回"找不到数据集"错误

---

### 第十二步：创建并分发解析任务

根据文档配置判断任务类型：

#### 分支 A：文档配置了 pipeline_id → DataFlow 任务
1. 获取文档的存储地址（bucket 和文件名）
2. 构建 DataFlow 任务记录：
   - 生成唯一任务 ID
   - 设置任务类型为 "dataflow"
   - 记录数据流 ID、文档 ID、优先级
3. 删除该文档的历史任务记录
4. 标记文档开始解析（设置进度消息和处理开始时间）
5. 批量插入任务到数据库
6. 将任务推入 Redis 队列

---

#### 分支 B：标准文档解析任务

**B-1 根据文档类型创建任务分片**

不同文件类型采用不同分片策略：

| 文件类型 | 分片方式 | 默认分片大小 |
|---------|---------|------------|
| PDF | 按页范围分多个任务 | 每 12 页一个任务 |
| 学术论文 | 按页范围分多个任务 | 每 22 页一个任务 |
| Excel/表格 | 按行数分多个任务 | 每 3000 行一个任务 |
| 整文档解析器 / 目录提取 | 不分片 | 整文档为一个任务 |
| 其他类型 | 不分片 | 整文件为一个任务 |

每个分片任务包含：
- 唯一任务 ID
- 文档 ID
- 起止位置（页范围或行范围）
- 初始进度 0%

**可能失败**：文件无法读取（如 PDF 页数获取失败）→ 默认页数为 0

---

**B-2 计算任务摘要（digest）**
1. 获取文档的完整分块配置（解析器类型、配置参数、页范围等）
2. 对所有配置字段排序后进行哈希（xxhash64）
3. 将文档 ID、起始页、结束页也纳入哈希
4. 每个分片任务得到唯一的摘要值

**用途**：后续判断任务配置是否变化，实现增量复用

---

**B-3 尝试复用历史任务的 chunks**
1. 查询该文档之前的历史任务记录
2. 如果存在历史任务：
   - 对比每个新任务与历史任务的摘要值
   - 如果摘要一致（说明分块配置未变），直接复用之前的 chunks
   - 收集无法复用的旧 chunk ID
   - 删除旧的任务记录
   - 从向量存储中删除无法复用的旧 chunks
3. 更新文档的 chunk 数为复用成功数

---

**B-4 入库与入队**
1. 将所有任务记录批量插入数据库（冲突时替换）
2. 标记文档开始解析：
   - 设置进度消息为 "Task is queued..."
   - 设置处理开始时间
   - 设置初始进度为 0~1% 的随机小值
3. 筛选出未完成的任务（进度 < 100%）
4. 将未完成的任务逐个推入 Redis 队列
   - 根据优先级分发到不同队列

**可能失败**：Redis 不可用 → 返回"无法访问 Redis"错误

---

### 第十三步：返回结果
1. **成功情况**：所有文档的任务均已成功创建 → 返回成功状态
2. **部分失败情况**：某些文档权限不足或不存在 → 返回对应错误信息

---

## 后台任务执行流程（独立进程）

任务推入 Redis 队列后，由独立的 **task_executor** 进程消费执行。

### 第十四步：任务消费主循环
1. 启动异步事件循环
2. 根据工作器编号计算启动延迟，交错启动（避免连接风暴）
3. 初始化全局配置
4. 启动心跳上报协程（定期上报执行器状态）
5. 通过并发信号量控制最大并行任务数
6. 循环创建任务管理器处理任务

---

### 第十五步：获取任务
1. 优先从未确认（UNACKED）队列获取任务（保证至少一次消费）
2. 如果未确认队列为空，从正常队列获取新任务
3. 支持多个优先级队列，按顺序消费
4. 根据任务类型获取完整任务信息：
   - GraphRAG / Canvas 调试任务 → 直接使用消息中的任务信息
   - 记忆保存任务 → 从数据库查询完整任务
   - 普通解析任务 → 从数据库查询完整任务
5. 检查任务是否已被取消（查询 Redis 中的取消标志）
6. 已取消的任务直接跳过并确认消息

---

### 第十六步：根据任务类型路由分发

| 任务类型 | 处理方式 |
|---------|---------|
| `memory` | 调用记忆服务保存对话记忆 |
| `dataflow` | 执行 Agent Canvas 配置的数据流任务 |
| `raptor` | 执行 RAPTOR 递归摘要聚合（受知识图谱并发限制） |
| `graphrag` | 执行 GraphRAG 知识图谱构建（受知识图谱并发限制） |
| 其他 | 走标准文档解析流程（第十七步至第二十一步） |

---

### 第十七步：绑定嵌入模型（标准解析流程开始）
1. 根据任务中的嵌入模型 ID 获取模型配置
2. 创建模型调用实例
3. 验证模型可用性

---

### 第十八步：初始化知识库索引
1. 获取知识库的向量维度配置
2. 确保向量存储中对应的索引存在
3. 如不存在则创建索引

---

### 第十九步：构建文档分块（build_chunks）

#### 19.1 获取文件数据
1. 根据文档 ID 获取存储地址（bucket 和文件名）
2. 从对象存储（MinIO/S3 等）下载文件二进制数据
3. 检查文件大小是否超出限制

**可能失败**：文件获取失败 → 任务失败，记录错误信息

---

#### 19.2 选择并执行解析器
1. 根据文档的 `parser_id` 选择对应的解析器
2. 调用解析器的分块方法，传入：
   - 文件名
   - 文件二进制数据
   - 解析配置（分块大小、分隔符等）
   - 页范围（from_page, to_page）
   - 语言设置
3. 解析器输出为 chunk 列表，每个 chunk 包含：
   - 文本内容
   - 位置信息（页码、坐标）
   - 图片（如有）
   - 权重

**可能失败**：不支持的文件格式 → 任务失败

---

#### 19.3 处理 chunk 中的图片
1. 遍历每个 chunk 的图片列表
2. 将 base64 编码的图片上传到对象存储
3. 生成图片 ID
4. 用图片 ID 替换 chunk 文本中的 base64 引用

---

#### 19.4 LLM 增强（可选，根据解析配置）

**自动生成关键词**（当 `auto_keywords > 0` 时）：
1. 对每个 chunk 的文本内容调用 LLM
2. 提取指定数量的关键词
3. 将关键词附加到 chunk

**自动生成问题**（当 `auto_questions > 0` 时）：
1. 对每个 chunk 的文本内容调用 LLM
2. 生成指定数量的相关问题
3. 将问题附加到 chunk

**自动生成元数据**（当 `enable_metadata = true` 时）：
1. 根据知识库定义的元数据 schema
2. 对每个 chunk 调用 LLM 提取元数据
3. 将元数据附加到 chunk

**自动标签分类**（当 `tag_kb_ids` 非空时）：
1. 根据目标知识库的标签体系
2. 对每个 chunk 进行自动分类打标

**可能失败**：LLM 调用失败 → 记录错误，任务可能部分完成

---

### 第二十步：向量嵌入（embedding）
1. 将 chunks 分批处理（每批 16 个）
2. 对每批 chunk：
   - 提取文本内容
   - 统计 token 消耗量
   - 调用嵌入模型生成向量
   - 获取向量维度
   - 将向量附加到每个 chunk（字段名：`q_{维度}_vec`）
3. 更新嵌入进度

---

### 第二十一步：插入 chunks 到文档存储
1. 构建 chunk 文档列表，每个包含：
   - chunk ID
   - 文档 ID
   - 知识库 ID
   - 文本内容（分词后）
   - 带权重文本
   - 向量数据
   - 关键词、问题、元数据（如有）
2. 批量写入向量存储（Elasticsearch 或 Infinity）
3. 更新任务进度为 100%（完成）
4. 更新文档和知识库的统计信息：
   - chunk 数量
   - token 数量
   - 处理耗时

---

### 第二十二步：任务完成与清理
1. 向 Redis 发送消息确认（ACK）
2. 记录流水线操作日志（用于审计）
3. 从当前任务列表中移除
4. 统计成功/失败数量

**异常处理**：
- 任务被取消 → 正常结束，不计为失败
- 任务执行异常 → 记录错误信息到进度消息，增加失败计数
- 任务超时（3 小时） → 自动终止，释放资源

## 业务规则总结

### 任务状态规则
| 状态值 | 含义 |
|-------|------|
| 0 | 成功（SUCCESS） |
| 1 | 运行中（RUNNING） |
| 2 | 取消（CANCEL） |
| 3 | 未开始（UNSTART） |

### 取消规则
- 只能取消处于"运行中"状态的任务
- 取消通过 Redis 标志位实现，不中断正在执行的代码
- 任务执行器在关键节点检查取消标志

### 重新运行规则
- 重新运行时会清理旧的统计数据
- 如果配置未变，会复用之前的 chunks（通过摘要比对）
- 如果配置变化，会删除旧 chunks 并重新解析

### 并发控制规则
- 全局并发任务数有上限（通过信号量控制）
- GraphRAG 和 RAPTOR 任务额外限制并发为 2（消耗大量 LLM token）
- 任务超时上限为 3 小时

### 异步执行规则
- 接口返回仅表示任务已创建，不等待执行完成
- 实际解析由后台 task_executor 进程执行
- 客户端通过轮询文档状态获取解析进度

## 输入输出

### 输入
| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| doc_ids | string[] | 是 | 文档 ID 列表 |
| run | string | 是 | 运行状态（0=成功, 1=运行, 2=取消） |
| delete | boolean | 否 | 是否删除已有解析结果 |
| apply_kb | boolean | 否 | 是否应用知识库配置 |

### 输出
| 字段 | 类型 | 说明 |
|------|------|------|
| code | number | 状态码（0=成功） |
| message | string | 提示信息 |
| data | boolean | true=操作成功 |

---

## 错误处理

| 错误场景 | 返回信息 |
|----------|----------|
| 未登录 | 认证失败 |
| 缺少 doc_ids | 参数错误 |
| 缺少 run | 参数错误 |
| 无文档权限 | No authorization. |
| 租户不存在 | Tenant not found! |
| 文档不存在 | Document not found! |
| 取消未运行的任务 | Cannot cancel a task not in RUNNING status |
| 知识库不存在 | Can't find this dataset! |
| Redis 不可用 | Can't access Redis. Please check the Redis' status. |

---

## 注意事项

1. **异步执行**：接口返回后任务仍在后台执行，前端需轮询状态
2. **批量处理**：支持一次提交多个文档，逐个处理
3. **幂等性**：重复运行相同配置的文档可复用已有 chunks
4. **分片并行**：PDF 按页范围、Excel 按行数分片，多任务并行解析
5. **取消安全**：取消操作通过标志位实现，不会中断正在执行的代码
6. **资源隔离**：GraphRAG/RAPTOR 有独立的并发限制，避免耗尽 LLM 配额
7. **超时保护**：单个任务最长 3 小时，超时自动终止
8. **至少一次消费**：Redis Stream ACK 机制保证任务不丢失
9. **交错启动**：多 worker 启动时错开时间，避免连接风暴

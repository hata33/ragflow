# 文本分块逻辑 - 业务逻辑步骤

## 概述

文本分块（Text Chunking）是 RAGFlow 文档处理流程中的核心环节，负责将文档原始内容转换为适合检索和向量嵌入的文本块。整个流程分为三个阶段：

1. **解析阶段**：根据文件类型选择解析器，将不同格式的文档转换为统一的文本段落（sections）列表
2. **分块阶段**：按照分隔符切分文本段落，智能合并为不超过 token 限制的文本块（chunks）
3. **分词阶段**：为每个文本块添加分词信息和权重，生成可用于 Elasticsearch 检索的文档结构

这三个阶段依次执行，前一个阶段的输出作为后一个阶段的输入，最终产出可被向量化和检索的 chunk 列表。

---

## 业务逻辑流程

### 第一阶段：解析 - 将文档转换为文本段落

---

#### 第一步：初始化配置参数

1. 判断文档语言是否为英文（影响后续分词策略）
2. 获取解析器配置参数：
   - `chunk_token_num`：单个文本块的最大 token 数（默认 512）
   - `delimiter`：分句分隔符（默认换行符及中英文标点）
   - `layout_recognize`：布局识别器类型（默认 DeepDOC）
   - `analyze_hyperlink`：是否分析超链接（默认开启）
   - `overlapped_percent`：相邻块之间的重叠百分比（默认 0）
3. 处理子元素分隔符（children_delimiter）：
   - 解析转义字符和自定义分隔符（反引号包裹的格式）
   - 按长度降序排序自定义分隔符（避免短分隔符误匹配）
   - 合并为正则表达式模式
4. 获取上下文配置：
   - `table_context_size`：表格前后保留的文本行数
   - `image_context_size`：图片描述保留的文本行数

---

#### 第二步：初始化文档元数据

1. 创建文档基础信息字典，包含：
   - `docnm_kwd`：文档名称（用于检索时关联来源文档）
   - `title_tks`：标题分词结果（去除文件扩展名后分词）
   - `title_sm_tks`：标题细粒度分词结果

---

#### 第三步：提取嵌入文件（仅根调用时执行）

1. 判断是否为根调用（非递归调用）
2. 如果是根调用，从文件二进制数据中提取嵌入的子文件
3. 对每个嵌入文件递归调用分块函数进行解析
4. 收集所有嵌入文件的解析结果

**可能失败**：嵌入文件解析失败 -> 记录错误日志，跳过该嵌入文件，继续处理其他嵌入文件

---

#### 第四步：根据文件类型选择解析路径

根据文件扩展名路由到对应的解析逻辑：

| 文件类型 | 扩展名 | 解析方式 |
|---------|--------|---------|
| Word 文档 | .docx | 使用 DOCX 解析器提取段落、表格、图片 |
| PDF 文档 | .pdf | 根据布局识别器选择解析器（DeepDOC / MinerU / Docling / TCADP / PaddleOCR / 纯文本） |
| Excel/CSV | .xlsx, .xls, .csv | 使用 Excel 解析器提取行数据 |
| 纯文本/代码 | .txt, .py, .js, .java 等 | 使用纯文本解析器 |
| Markdown | .md, .markdown, .mdx | 使用 Markdown 解析器提取文本、表格、图片 |
| HTML 网页 | .htm, .html | 使用 HTML 解析器 |
| EPUB 电子书 | .epub | 使用 EPUB 解析器 |
| JSON 数据 | .json, .jsonl, .ldjson | 使用 JSON 解析器 |
| 旧版 Word | .doc | 使用 Apache Tika 解析器 |
| 其他 | - | 不支持，抛出异常 |

**可能失败**：不支持的文件类型 -> 抛出"文件类型不支持"异常

---

#### 第五步：DOCX 文档解析

1. **超链接分析**（可选，根据配置）：
   - 提取文档中的所有超链接 URL
   - 逐个访问超链接，下载网页内容
   - 递归调用分块函数解析网页
2. **修复兼容性问题**：
   - 修复 python-docx 库的已知问题（"word/NULL" 错误）
3. **解析文档结构**：
   - 遍历文档的所有段落和表格
   - 提取文本内容、嵌入图片、表格
   - 识别标题层级（支持 7 级标题）
   - 为表格添加标题层级路径信息
   - 追踪页码变化
4. **规范化文本**：
   - 对 RTL（从右到左）语言的文本进行规范化处理
5. **DOCX 专用分块**：
   - 使用 DOCX 专用分块算法，合并段落为不超过 token 限制的块
   - 保留表格和图片的上下文关联
6. **视觉增强**（可选）：
   - 使用视觉模型理解文档中的图片内容
7. **分词包装**：
   - 为每个块添加分词信息，识别文本、图片、表格类型

---

#### 第六步：PDF 文档解析

1. **确定解析器**：
   - 规范化布局识别器名称
   - 从解析器注册表中选择对应的解析函数
   - 支持的解析器：DeepDOC（默认）、MinerU、Docling、TCADP、PaddleOCR、纯文本
2. **超链接提取**（可选，根据配置）
3. **调用解析器**：
   - 传入页码范围（from_page, to_page）
   - 执行 OCR、布局分析、表格识别
   - 输出文本段落（sections）和表格（tables）
4. **规范化文本**：对 RTL 语言文本进行规范化
5. **检查解析结果**：
   - 如果段落和表格均为空 -> 返回空结果
6. **上下文增强**（可选）：
   - 为表格和图片添加前后文上下文信息
7. **特殊解析器处理**：
   - 某些解析器（TCADP、Docling、MinerU、PaddleOCR）已内置分块逻辑，跳过后续分块
8. **表格分词**：
   - 将表格数据转换为可检索的文档块

**可能失败**：PDF 页数获取失败 -> 默认页数为 0；OCR 解析失败 -> 返回空结果

---

#### 第七步：Excel/CSV 表格解析

1. **判断解析器类型**：
   - 如果配置了 TCADP 解析器 -> 使用腾讯云解析
   - 否则 -> 使用默认 DeepDOC 解析器
2. **TCADP 解析路径**：
   - 检查 TCADP 服务可用性
   - 确定文件类型（XLSX 或 CSV）
   - 调用云端解析服务
   - 禁用后续分块（表格已是独立行）
3. **默认解析路径**：
   - 如果配置了 HTML 输出 -> 每 12 行生成一组 HTML 表格
   - 否则 -> 每行独立输出为纯文本

**可能失败**：TCADP 服务不可用 -> 返回空结果并提示配置错误

---

#### 第八步：TXT 纯文本/代码文件解析

1. 使用纯文本解析器
2. 传入 token 限制和分隔符配置
3. 按分隔符将文本切分为段落

---

#### 第九步：Markdown 文档解析

1. **解析 Markdown 结构**：
   - 提取文本段落、表格、图片
   - 按分隔符分段
   - 为每个段落加载关联的图片
   - 合并同一段落的多个图片
2. **视觉模型检测**（可选）：
   - 检测是否配置了视觉模型
   - 如果有，为每个段落的图片生成描述
3. **图片内容增强**（如果有视觉模型）：
   - 使用视觉模型理解图片内容
   - 将图片描述追加到段落文本
4. **超链接提取**（可选）
5. **表格分词**

---

#### 第十步：HTML/EPUB/JSON/DOC 文件解析

1. **HTML**：使用 HTML 解析器提取文本段落
2. **EPUB**：使用 EPUB 解析器提取电子书内容
3. **JSON**：使用 JSON 解析器按 token 限制提取数据
4. **DOC**：
   - 检查 Apache Tika 是否可用
   - 调用 Tika 解析器提取文本
   - 按换行符分段

**可能失败**：Tika 不可用 -> 返回空结果；Tika 解析内容为空 -> 返回空结果

---

### 第二阶段：分块 - 智能合并段落为文本块

---

#### 第十一步：获取重叠百分比配置

1. 读取配置中的 `overlapped_percent` 参数
2. 规范化重叠百分比值（确保有效范围）

---

#### 第十二步：Markdown 专用分块逻辑

当文件为 Markdown 格式时，使用专用分块逻辑：

1. 获取 token 限制（`chunk_token_num`）
2. 初始化当前文本块和累计 token 数
3. 逐段落遍历：
   - 计算当前段落的 token 数
   - 如果追加后超出 token 限制 -> 保存当前块，开始新块
   - 计算重叠部分：
     - 按百分比从当前块末尾截取文本
     - 将重叠文本作为新块的起始内容
   - 追加新段落到当前块
   - 合并段落关联的图片
4. 添加最后一个未满的块
5. 根据是否包含图片选择对应的分词方法

---

#### 第十三步：通用分块逻辑（非 DOCX、非 Markdown 格式）

1. **检查图片关联**：
   - 如果所有段落都没有关联图片 -> 清除图片列表
2. **带图片的分块**（naive_merge_with_images）：
   - 文本和图片一一对应
   - 同一块中的多张图片垂直拼接
   - 按 token 限制合并文本
   - 处理重叠百分比
3. **标准分块**（naive_merge）：
   - **自定义分隔符处理**：
     - 如果分隔符中包含反引号包裹的自定义分隔符
     - 按自定义分隔符切分文本，每个片段作为独立块
     - 按长度降序匹配，避免短分隔符误匹配
   - **标准处理流程**：
     - 逐段落遍历
     - 计算每段 token 数
     - 如果当前块为空或已超过 token 限制的阈值 -> 创建新块
     - 否则追加到当前块
     - 处理重叠：从上一个块的末尾按百分比截取文本，作为新块的起始内容
     - 如果文本 token 数小于 8，不附加位置信息

---

#### 第十四步：表格独立分块

1. 表格数据单独处理，不参与文本分块流程
2. 字符串格式的表格 -> 直接作为一个文档块
3. 列表格式的表格 -> 按批次（每批 10 行）合并为文档块
4. 使用分隔符连接行（英文用 `"; "`，中文用 `"； "`）
5. 为表格块添加类型标记（`doc_type_kwd = "table"`）
6. 如果表格没有 `<tr>` 标签 -> 标记为图片类型（`doc_type_kwd = "image"`）

---

### 第三阶段：分词 - 为文本块添加检索信息

---

#### 第十五步：为文本块添加文档元数据

1. 深拷贝文档元数据模板
2. 将文档名称（`docnm_kwd`）、标题分词（`title_tks`、`title_sm_tks`）复制到每个块

---

#### 第十六步：提取位置和图片信息（PDF 专用）

1. 如果提供了 PDF 解析器：
   - 从 PDF 中裁剪对应区域的图片
   - 提取文本在页面中的位置信息（页码、坐标）
   - 移除文本中的位置标签
2. 如果未提供 PDF 解析器：
   - 添加默认位置信息（块索引作为序号）

---

#### 第十七步：子元素分隔符处理

如果配置了子元素分隔符（children_delimiter）：

1. 将原始文本保存为 `mom_with_weight`（母块完整文本）
2. 使用正则表达式按分隔符切分文本
3. 为每个子块独立添加分词信息
4. 子块继承母块的文档元数据和位置信息

**可能失败**：正则表达式无效 -> 记录警告，将整个文本作为单个块处理

---

#### 第十八步：核心分词处理

对每个文本块执行分词：

1. **保存原始文本**：将文本保存到 `content_with_weight` 字段
2. **清理文本**：移除 HTML 表格标签（`<table>`、`<td>`、`<tr>` 等），避免影响分词
3. **生成长 token 分词**（`content_ltks`）：
   - 中文：使用 jieba 分词器进行分词
   - 英文：使用空格分词
4. **生成短 token 分词**（`content_sm_ltks`）：
   - 对长 token 分词结果进行细粒度再分词
   - 用于高精度的文本匹配

---

#### 第十九步：超链接递归解析（仅根调用时执行）

1. 如果配置了超链接分析且存在提取的 URL
2. 逐个访问超链接，下载网页内容
3. 尝试按原始 URL 的文件类型解析
4. 如果失败 -> 按 HTML 格式解析
5. 将解析结果合并到最终结果中

---

#### 第二十步：合并所有结果

1. 将以下来源的结果合并为最终列表：
   - 主文档的分块结果
   - 嵌入文件的解析结果（embed_res）
   - 超链接的解析结果（url_res）
2. 返回完整的分块结果列表

---

## 分块策略规则

### chunk_token_num 调优

| 场景 | 推荐值 | 说明 |
|------|--------|------|
| 精确检索（FAQ、短文本） | 128~256 | 较小的块保证检索精度 |
| 通用场景 | 512（默认） | 平衡精度和上下文完整性 |
| 长文本理解（论文、报告） | 1024~2048 | 保留更多上下文信息 |
| 禁用分块 | 0 | 表格或已分块内容直接使用 |

### delimiter 选择规则

| 类型 | 示例 | 说明 |
|------|------|------|
| 默认分隔符 | `\n!?。；！？` | 换行符和中英文句末标点 |
| 自定义分隔符 | `` `##` ``、`` `---` `` | 反引号包裹，用于 Markdown 标题等 |
| 子元素分隔符 | children_delimiter | 用于嵌套内容的二次切分 |

**分隔符优先级**：自定义分隔符优先于默认分隔符处理，且按长度降序匹配。

### overlap（重叠）规则

- `overlapped_percent = 0`：无重叠，相邻块之间完全分离
- `overlapped_percent > 0`：相邻块之间有重叠内容
  - 重叠内容取自上一个块末尾的指定百分比长度
  - 用于保留上下文连贯性，提高检索质量
  - 重叠计算基于字符长度而非 token 数

## 输入输出

### 输入

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| filename | string | 是 | 文件名（含扩展名，用于判断文件类型） |
| binary | bytes | 否 | 文件二进制内容（与 filename 二选一） |
| from_page | number | 否 | 起始页码（默认 0，PDF 专用） |
| to_page | number | 否 | 结束页码（默认 100000，PDF 专用） |
| lang | string | 否 | 语言设置（默认 "Chinese"，影响分词策略） |
| callback | function | 否 | 进度回调函数 |
| parser_config | object | 否 | 解析器配置（包含分块参数） |
| tenant_id | string | 否 | 租户 ID（使用视觉模型时必需） |

### parser_config 子参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| chunk_token_num | number | 512 | 单个文本块的最大 token 数 |
| delimiter | string | `"\n!?。；！？"` | 分句分隔符 |
| layout_recognize | string | "DeepDOC" | 布局识别器类型 |
| analyze_hyperlink | boolean | true | 是否分析并递归解析超链接 |
| overlapped_percent | number | 0 | 相邻块重叠百分比 |
| table_context_size | number | 0 | 表格上下文保留行数 |
| image_context_size | number | 0 | 图片上下文保留行数 |
| children_delimiter | string | "" | 子元素分隔符（用于嵌套内容切分） |

### 输出

返回分块结果列表，每个元素为字典格式：

| 字段 | 类型 | 说明 |
|------|------|------|
| docnm_kwd | string | 来源文档名称 |
| title_tks | string | 文档标题分词结果 |
| title_sm_tks | string | 文档标题细粒度分词结果 |
| content_with_weight | string | 文本块原始内容 |
| content_ltks | string | 长 token 分词（用于检索） |
| content_sm_ltks | string | 短 token 分词（用于高精度匹配） |
| image | object | 关联的图片对象（如有） |
| doc_type_kwd | string | 块类型标记（text / table / image） |
| page_num_int | list | 页码列表（PDF 专用） |
| position_int | list | 位置坐标列表（PDF 专用） |
| mom_with_weight | string | 母块完整文本（使用子分隔符时） |

## 错误处理

| 错误场景 | 处理方式 |
|----------|----------|
| 不支持的文件类型 | 抛出"文件类型不支持"异常 |
| 嵌入文件解析失败 | 记录错误日志，跳过该文件，继续处理 |
| PDF OCR 解析失败 | 返回空结果 |
| PDF 页数获取失败 | 默认页数为 0 |
| MinerU/Docling/PaddleOCR 未安装 | 通过回调返回未找到提示，返回空结果 |
| TCADP 服务不可用 | 通过回调返回配置错误提示，返回空结果 |
| Apache Tika 不可用（.doc 文件） | 通过回调返回不可用提示，返回空结果 |
| Tika 解析内容为空 | 记录警告日志，返回空结果 |
| 正则表达式分隔符无效 | 记录警告，将整个文本作为单个块 |
| 超链接网页下载失败 | 跳过该超链接，尝试按 HTML 格式重新解析 |
| 文件二进制内容为空且需要提取嵌入文件 | 抛出"不支持从文件路径提取嵌入文件"异常 |
| PDF 解析器返回空段落和空表格 | 直接返回空结果列表 |

---

## 注意事项

1. **递归调用**：分块函数支持递归调用，嵌入文件和超链接都会递归解析。通过 `is_root` 参数区分根调用和递归调用，避免重复提取嵌入文件
2. **文件类型优先级**：文件类型通过扩展名判断，优先匹配 DOCX，其次 PDF，依次类推。扩展名匹配不区分大小写
3. **RTL 文本支持**：所有文件类型解析后都会进行 RTL（从右到左）文本规范化，支持阿拉伯语等语言
4. **表格独立处理**：表格数据不参与文本分块流程，而是独立进行分词和类型标记。字符串表格直接作为块，列表表格按批次合并
5. **图片合并**：同一文本块中的多张图片会被垂直拼接为一张图片，使用 PIL 库处理
6. **分块算法选择**：根据是否包含图片选择不同的分块算法。有图片时使用带图片的分块算法，无图片时使用标准分块算法
7. **DOCX 特殊处理**：DOCX 文档在解析阶段直接完成分块和分词，不经过通用分块逻辑。支持表格标题层级追踪和上下文增强
8. **Markdown 特殊处理**：Markdown 文档使用专用分块逻辑，保留段落与图片的对应关系，支持视觉模型增强图片理解
9. **Token 计数**：文本块的 token 数通过 `num_tokens_from_string` 函数计算，与实际嵌入模型的 token 计算方式一致
10. **进度报告**：解析过程通过回调函数报告进度百分比和状态消息，供前端展示

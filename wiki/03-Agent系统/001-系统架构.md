## 描述

RAGFlow Agent 是基于可视化画布的工作流编排系统，采用插件式组件架构。核心引擎在 `agent/canvas.py` 中实现，包含 Canvas 执行引擎和 Graph 结构管理。系统支持 20+ 组件类型、动态组件加载、变量引用、流程控制和事件流推送。

## 核心设计理念

```
可视化编排 + 插件式组件 + 事件流驱动 = 灵活的 AI 应用平台
```

## Canvas 执行引擎

### Graph (父类)

职责：结构管理

```python
class Graph:
    - load_dsl()        # 加载 DSL 配置
    - load_components() # 加载组件实例
    - manage_path()     # 管理执行路径
```

### Canvas (子类)

职责：执行控制

```python
class Canvas(Graph):
    - run()             # 工作流执行
    - _run_batch()      # 批量并发执行
    - _control_flow()   # 流程控制
    - _push_event()     # 事件推送
```

## 执行流程

```
1. 初始化阶段
   ├── 解析 DSL 配置
   ├── 加载所有组件
   ├── 初始化全局变量
   └── 设置执行路径

2. 执行循环
   ├── 批量执行组件 (并发控制)
   ├── 处理流式输出
   ├── 异常处理与恢复
   └── 决定下一个执行节点

3. 流程控制
   ├── Categorize/Switch → 条件分支
   ├── Iteration/Loop → 循环控制
   ├── ExitLoop → 跳出循环
   └── 默认 → 顺序执行下游

4. 结束处理
   ├── 发送完成事件
   ├── 保存执行历史
   └── 清理资源
```

## 事件流系统

### 事件类型

```
workflow_started    → 工作流开始
    │
    ├── node_started     → 节点开始执行
    │   │
    │   ├── message      → 消息内容 (流式)
    │   │   ├── content
    │   │   ├── start_to_think
    │   │   └── end_to_think
    │   │
    │   ├── message_end   → 消息结束
    │   │
    │   └── node_finished → 节点执行完成
    │
    └── workflow_finished → 工作流结束
```

### 事件结构

```json
{
  "event": "node_started",
  "message_id": "uuid",
  "task_id": "uuid",
  "created_at": 1234567890,
  "data": {
    "component_id": "begin",
    "component_name": "开始",
    "component_type": "Begin",
    "thoughts": "思考内容..."
  }
}
```

## 设计模式

| 模式 | 应用场景 |
|------|----------|
| 责任链模式 | path 数组管理组件执行顺序 |
| 策略模式 | 不同组件的差异化流程控制 |
| 观察者模式 | 事件流系统通知前端更新 |
| 模板方法 | ComponentBase 定义执行模板 |

## 性能优化

### 并发控制

```
Semaphore (信号量)
    ├── 限制最大并发数 (默认 10)
    ├── 防止资源耗尽
    └── 支持环境变量配置
```

### 批量执行

```
_run_batch(f, t)
    ├── 收集一批组件
    ├── 创建异步任务
    ├── 并发执行
    └── 等待全部完成
```

### 流式输出

```
LLM 生成
    ├── 逐 token 生成
    ├── 实时推送到前端
    └── 降低首字延迟
```

## 与 LangGraph 对比

| 特性 | RAGFlow Agent | LangGraph |
|------|---------------|-----------|
| 设计范式 | 基于类的组件 | 基于函数的节点 |
| 状态管理 | 全局变量 + 组件输出 | 统一 State 对象 |
| 变量引用 | 专用语法 `{@}` | 直接访问 state |
| 可视化 | 内置画布编辑器 | 需要第三方工具 |
| 流式输出 | 原生支持 | 需要手动实现 |

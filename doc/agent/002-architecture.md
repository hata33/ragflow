# RAGFlow Agent 架构设计文档

## 概述

RAGFlow Agent 是一个基于**可视化画布**的工作流编排系统，采用**插件式组件架构**，支持灵活的 AI 应用构建。

## 核心设计理念

```
可视化编排 + 插件式组件 + 事件流驱动 = 灵活的 AI 应用平台
```

## 核心模块设计

### 1. 插件式组件系统

#### 设计目标
- **松耦合**：组件间通过标准接口通信
- **可扩展**：新增组件无需修改核心代码
- **易维护**：每个组件独立封装

#### 架构设计

```
ComponentBase (抽象基类)
    │
    ├── 定义统一接口 (_invoke, get_input, set_output)
    ├── 提供公共功能 (变量解析、异常处理、取消检查)
    │
    └── 具体组件 (继承实现)
        ├── Begin → 入口组件
        ├── Message → 消息输出
        ├── LLM → 大模型调用
        ├── Categorize → 条件分支
        └── ... (20+ 组件)
```

#### 动态加载机制

```
component_class("Begin")
    │
    ├── 查找 agent.component 模块
    │   └── 找到 → 返回 Begin 类
    │
    ├── 查找 agent.tools 模块
    │   └── 找到 → 返回工具类
    │
    └── 查找 rag.flow 模块
        └── 找到 → 返回流程类
```

**优势**：
- 新增组件只需在对应目录创建文件
- 无需修改核心代码
- 支持热加载

### 2. Canvas 执行引擎

#### 职责划分

```
Canvas (执行引擎)
    │
    ├── Graph (父类 - 结构管理)
    │   ├── 加载 DSL 配置
    │   ├── 管理组件实例
    │   └── 维护执行路径
    │
    └── Canvas (子类 - 执行控制)
        ├── 全局变量管理 (globals, variables)
        ├── 工作流执行 (run 方法)
        ├── 流程控制 (循环、分支、异常)
        └── 事件流生成
```

#### 执行流程

```
1. 初始化阶段
   ├── 解析 DSL 配置
   ├── 加载所有组件
   ├── 初始化全局变量
   └── 设置执行路径

2. 执行循环
   ├── 批量执行组件 (并发控制)
   ├── 处理流式输出
   ├── 异常处理与恢复
   └── 决定下一个执行节点

3. 流程控制
   ├── Categorize/Switch → 条件分支
   ├── Iteration/Loop → 循环控制
   ├── ExitLoop → 跳出循环
   └── 默认 → 顺序执行下游

4. 结束处理
   ├── 发送完成事件
   ├── 保存执行历史
   └── 清理资源
```

#### 关键设计模式

| 模式 | 应用场景 |
|------|----------|
| **责任链模式** | path 数组管理组件执行顺序 |
| **策略模式** | 不同组件的差异化流程控制 |
| **观察者模式** | 事件流系统通知前端更新 |
| **模板方法** | ComponentBase 定义执行模板 |

### 4. 事件流系统

#### 事件类型

```
workflow_started    → 工作流开始
    │
    ├── node_started     → 节点开始执行
    │   │
    │   ├── message      → 消息内容 (流式)
    │   │   ├── content
    │   │   ├── start_to_think
    │   │   └── end_to_think
    │   │
    │   ├── message_end   → 消息结束
    │   │
    │   └── node_finished → 节点执行完成
    │
    └── workflow_finished → 工作流结束
```

#### 事件结构

```json
{
  "event": "node_started",
  "message_id": "uuid",
  "task_id": "uuid",
  "created_at": 1234567890,
  "data": {
    "component_id": "begin",
    "component_name": "开始",
    "component_type": "Begin",
    "thoughts": "思考内容..."
  }
}
```

#### 前后端交互

```
前端 (SSE/WebSocket)
    │
    ├── 监听事件流
    ├── 实时更新 UI
    │   ├── 显示节点状态
    │   ├── 流式输出消息
    │   └── 展示执行进度
    │
    └── 用户交互
        ├── 取消执行
        ├── 提供输入 (UserFillUp)
        └── 修改参数
```

### 5. 流程控制机制

#### 控制组件

```
┌─────────────────────────────────────────────────────────┐
│                    流程控制组件                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Categorize    → 条件分支（根据输出选择不同路径）       │
│  Switch        → 多路分支（类似于 switch-case）          │
│  Iteration     → 列表迭代                               │
│  Loop          → 条件循环                               │
│  ExitLoop      → 退出循环                               │
│  UserFillUp    → 等待用户输入                           │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

#### 路径动态构建

```
执行路径 (path)
    │
    ├── 初始: ["begin"]
    │
    ├── 执行 begin 后: ["begin", "retrieval", "llm"]
    │
    ├── categorize 分支:
    │   ├── 输出 "category_a" → ["begin", ..., "categorize", "process_a"]
    │   └── 输出 "category_b" → ["begin", ..., "categorize", "process_b"]
    │
    └── loop 循环:
        ├── 每次迭代回到 loop_start
        └── exitloop 跳到 loop_end
```

## 扩展性设计

### 添加新组件

```
1. 创建组件文件
   agent/component/my_component.py

2. 定义组件类
   class MyComponent(ComponentBase):
       component_name = "MyComponent"
       def _invoke(self, **kwargs):
           # 实现逻辑
           pass

3. 自动注册
   __init__.py 自动发现并加载

4. 前端配置
   添加组件配置到组件库
```

### 添加新变量类型

```
1. 定义变量前缀
   例如: "custom.*"

2. 扩展解析逻辑
   在 get_variable_value 中添加处理

3. 更新文档
   说明新变量的用途
```

## 性能优化

### 并发控制

```
Semaphore (信号量)
    │
    ├── 限制最大并发数 (默认 10)
    ├── 防止资源耗尽
    └── 支持环境变量配置
```

### 批量执行

```
_run_batch(f, t)
    │
    ├── 收集一批组件
    ├── 创建异步任务
    ├── 并发执行
    └── 等待全部完成
```

### 流式输出

```
LLM 生成
    │
    ├── 逐 token 生成
    ├── 实时推送到前端
    └── 降低首字延迟
```

## 错误处理

### 异常处理策略

```
组件执行异常
    │
    ├── 检查异常配置
    │   ├── goto → 跳转到指定组件
    │   ├── default_value → 使用默认值
    │   └── 无配置 → 抛出异常
    │
    └── 记录错误日志
        ├── 组件 ID
        ├── 错误信息
        └── 执行上下文
```

### 取消机制

```
用户取消
    │
    ├── 设置 Redis 标志
    │   └── "{task_id}-cancel"
    │
    ├── 组件定期检查
    │   └── check_if_canceled()
    │
    └── 及时停止执行
        ├── 保存当前状态
        └── 释放资源
```

## 与 LangGraph 的对比

| 特性 | RAGFlow Agent | LangGraph |
|------|---------------|-----------|
| **设计范式** | 基于类的组件 | 基于函数的节点 |
| **状态管理** | 全局变量 + 组件输出 | 统一 State 对象 |
| **变量引用** | 专用语法 `{@}` | 直接访问 state |
| **可视化** | 内置画布编辑器 | 需要第三方工具 |
| **流式输出** | 原生支持 | 需要手动实现 |
| **扩展性** | 插件式自动加载 | 需要手动注册 |

## 总结

RAGFlow Agent 的架构设计具有以下特点：

1. **高度模块化**：组件独立封装，职责清晰
2. **插件式架构**：动态加载，易于扩展
3. **事件驱动**：实时状态更新，用户体验好
4. **流程灵活**：支持复杂的控制流
5. **容错性强**：完善的异常处理和取消机制

这种设计使得 RAGFlow Agent 既可以快速构建简单的 AI 应用，也能支撑复杂的企业级工作流。
